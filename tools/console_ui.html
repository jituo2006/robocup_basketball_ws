系统（上电后先点这个）

🔌 CAN + 电机使能 = 查 PCAN 适配器 → 不行就恢复 can0 → 单起 rb_chassis（真下发 CAN）→ 等「底盘已使能 4 个电机」。
只调底盘时用这个，不用起雷达/相机那一整套。
⚡ 一键启动流程 = 跑 boot.sh → 等「底盘已使能 + mission 就绪」→ 自动做就绪检查。
更细的手动排查用右边那两个按钮。

起任务（一局）

急停 = 下发 estop + 零速。永远优先按车上电源开关。

机构文本指令（这台机构的真实协议）

协议：STOP 停 · ZERO 初始化 · MOVE 1 90 5 抓取 · MOVE 1 0 5 放下。
开机顺序：先 STOP，再 ZERO 初始化，然后 MOVE（点上面那个「STOP + ZERO 初始化」）。
⚠️ 走的是服务 /rb_launcher/text，和上面那排二进制帧按钮 （Launch.srv）是两套协议 —— 这台机构只认文本。
行尾默认 \n；固件若要 \r\n， 改 launcher.yaml 的 line_ending。

机构（拿球 / 发球）

服务 /rb_launcher/launch；0=SHOOT 1=FAST 2=DRIBBLE 3=DBL 4=爪 5=滑道 7=STOP

导航（仅 IDLE 下可用）

雷达找球（粗）+ 相机精定位（细）

—
为什么值得做：雷达不受光照影响、FOV 360°（相机才约 60°，球在侧后方就瞎了）、 直接测距（相机是单目测距，靠球径先验，误差大）。
融合 = 相机为主（类别准、横向精度高）+ 雷达补相机看不到的球。
调参顺序：先看 z_min/z_max 能不能框住地面 → 再调球半径 → 最后调配对阈值。 参数只作用于控制台这份，不写回 yaml；调好再手动填进 perception.yaml。

抓球并放下（机构序列调试）

—
动作码：0=发射 1=快发 2=运球 3=双运球 4=夹爪(翻转) 5=滑轨(翻转) 6=循环 7=停
为什么做成"步骤表"：运球/双运球/夹爪/滑轨的物理语义在下位机固件里， 本仓库看不到 —— 到底哪步是"抓住"、哪步是"松开"只有上车试才知道。 所以给几个预设，现场哪个对就用哪个。
夹爪/滑轨是开关语义：每发一次翻转一次。脚本会记录翻了几次 （偶数=回到初始态），日志里能看到。
⚠️ 会真动机构：点之前确认机械周围没人、球在位、随时能断电。 不确定就先点「🧪 干跑」把步骤表打印出来看看。

点动（按住即走，自动停）

每次 0.4 秒后自动归零；底盘 200ms 超时是第二道保险。

📷 双摄像头实时画面

前摄 · /camera/image_raw/compressed
等待前摄曝光范围…
后摄 · /camera_rear/image_raw/compressed
等待后摄曝光范围…
—
曝光范围、步长和当前值均由各摄像头驱动读取，使用驱动原始单位。 应用手动值会关闭该路自动曝光；数值越大通常越亮，也可能降低帧率。 此处调整实时生效，重启相机后恢复配置文件设置。
两路都是 MJPEG 实时流。**前摄**朝车头（找球用），**后摄**朝车尾 （转 180° 后对着球，做精准定位 + 闭环后退）。
⚠️ 浏览器对同一个域名有并发连接上限，MJPEG 每路都占一条**长连接** —— 如果偶尔有一路不动，刷新页面即可（不是节点问题）。

📡 雷达俯视图（/cloud_registered）

局部相对坐标：启动时车体中心为 (0,0)，初始车头方向为 +x，左侧为 +y。当前采用车头朝上视图，不叠加场地图；场地导航尚未标定。
官方图（默认）= 与官方场地图方向一致：出发区 A 在左上、篮筐在右中。 （依赖下面的 x/y 方向开关）
ROS标准 = x→右、y→上（RViz 俯视）。
车头朝上 = 以车为中心、车头永远朝上（看"球在我哪一侧"方便）。
x/y 方向开关 = 单独翻某个轴；现场对着实物核对不准时用这个微调。
