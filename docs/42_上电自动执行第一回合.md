# 上电自动执行第一回合传球

2026-10-15。使用场景：NUC已开机，底盘和雷达/相机等传感器由同一个总开关一起上电。车应已放回A出发位、朝向正确，首球预装。

## 触发信号和流程

目前底盘上位机没有已验证的电源反馈或电机板心跳。CAN网口存在只代表适配器接入，不能代表电机板有电。第一版用共用电源的雷达IP `192.168.1.138` 从不可达变为可达作为总开关上电代理；这不是直接测量电机板电源。若雷达与底盘分开供电，必须更换触发源后再启用，不能沿用这个假设。

1. NUC开机后systemd服务后台等待。必须先观测到雷达连续离线至少3秒，再观测到上线；启动服务时雷达已经在线不会立即发车。
2. 检测到雷达上线后立即记录单调时钟时刻，并记录本次运行状态（不锁定后续启动）。等待配置的can0出现，调用boot.sh启动底盘、雷达、视觉、定位、机构；`start_mission:=false`避免独立mission抢速度话题。启动前发现已有其它已知运动脚本则结束，不抢占它。
3. 从雷达上线开始的5秒与软件准备并行。节点进程出现后调用`run_first_round.sh --mechanism --power-on-monotonic ...`。复用第一回合原有等待，只补足尚未等完的部分，不是5秒+5秒。
4. 自动入口额外等待实际行驶定位、前后摄当前检测流（允许未识别到球）、已连接的机构串口状态及文本服务；cmd_vel不得存在其它发布者。只监听，不发送机构测试指令。数据未就绪保持原地等待；因此不能承诺物理开关合上后恰好第5秒发车，检测延迟和传感器初始化可能使实际启动更晚。
5. 执行现有完整第一回合：预装球去传球点→49度朝向→vesc_status/vesc_home/vesc_shoot 3→中线取第二球→传球点再次发射→回A区恢复初始朝向。沿用第1回合0.5空车/0.35载球走线及原识球取球速度。
6. 完成、失败后结束本次监视；控制进程先退出请求零速，再关闭本服务启动的软件栈。systemd在2秒后重新启动监视器，恢复等待下一次断电→上电；状态文件仅记录结果，不禁止后续启动。当前已经在线不会立即发车。急停禁止须手动复位，手动systemctl stop不会被自动重启。

服务使用`Restart=always`并关闭启动频率封锁，正常结束和异常退出后均恢复监视。`--enable`安装后验证服务已启用且运行；NUC每次开机都会启动后台监视器。开机时雷达已在线仍须先断电至少3秒再上电，不会因重启NUC直接发车。

雷达 ping 只检测初始上电边沿。触发后不再以 ping 结果中止任务。定位/视觉暂缺或延迟时发零速等待，恢复后继续；没有等待总时限。机构服务请求发出后等待同一个请求回复，不因回复慢重复发送。急停和底盘指令失联归零保留。

## 文件与参数

- `tools/auto_round1.py`：无ROS依赖的上电监视/进程监督。
- `tools/auto_round1.json`：NUC工作空间、共电雷达IP、明确的CAN接口、轮询间隔、上电边沿离线防抖和状态目录。
- `tools/autostart/robocup-auto-round1.service`：systemd模板。
- `tools/install_auto_round1.sh`：安装服务；默认只安装，显式`--enable`才启用。
- `tools/test_perimeter_ball.py --power-on-monotonic`：自动启动入口，固定完整第1回合传球、预装球、机构开启；人工启动不传此参数，仍等待原来的5秒。

每次执行从同一份`tools/match_rounds.json`读取启动延时、路线和速度，未改既有机构串口命令。自动入口读取/rb_launcher/ok的新消息（状态节点每秒发布，接收超过2.5秒不算当前就绪），只能证明串口连接而非实际入仓/发射成功。

## NUC操作

```bash
cd /home/user/robocup_basketball_ws
# 只读检查，不启动ROS/运动/机构
python3 tools/auto_round1.py --check

# 首次安装并启用后台等待
sudo bash tools/install_auto_round1.sh --enable
sudo systemctl status robocup-auto-round1.service
journalctl -u robocup-auto-round1.service -f
```

停止自动功能：

```bash
sudo systemctl disable --now robocup-auto-round1.service
```

正常完成或失败后会自动恢复监视，下一轮先断开底盘/传感器总开关至少3秒，摆回A区并预装球，确认日志正在等上电后再合总开关。急停或手动停止后需要人工恢复：

```bash
# 先断开底盘/传感器总开关，将车摆回A区并预装球。
sudo systemctl stop robocup-auto-round1.service
python3 tools/auto_round1.py --reset
sudo systemctl start robocup-auto-round1.service
# 确认日志正在等上电，再合总开关。
```

`bash tools/panic.sh`先禁止/停止自动服务，再执行原有急停流程；复位前不会再次自动发车。状态记录与复位不能证明场地/人员已经准备好，操作员必须在合总开关前完成准备。

## 验证边界

模拟覆盖离线→上线、启动时已在线不触发、5秒不重复等待、CAN/节点/相机/机构未就绪不发车、已有控制脚本不抢占、运行中ping丢失不中止、退出顺序、历史失败不锁定新电源边沿、启动时已在线不重跑、人工启动保持原延时。尚未做真实上电/两次传球/实车回位验收。
