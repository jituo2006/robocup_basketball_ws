# 14 · 综合控制台（一页操作 + 全网可视化）

> 一个网页搞定：**起/停整套软件 · 点按钮起任务 · 看实时日志 · 看相机画面 · 看雷达俯视图 ·
> 看小车情况（持球/区域/子系统 ok）· 看硬件链路（CAN/雷达/机构串口）**。

---

## 一、为什么是网页而不是 Qt 窗口

本机**没装 Qt**（PyQt/PySide 都没有），但有 `flask`。而且网页版有两个实际好处：

1. **相机画面和雷达俯视图直接用 MJPEG 推流** —— 不用把图像往 GUI 控件里搬；
2. **手机/另一台电脑连上就能当遥控台** —— 现场操作员不用挤在 NUC 前面。

---

## 二、启动

```bash
cd ~/robocup_basketball_ws
bash tools/console.sh                  # 默认 8090
bash tools/console.sh --port 9000      # 换端口
bash tools/console.sh --no-stack-control   # 禁止页面上起/停整套（更安全）
```

脚本会打印两个地址：

```
本机:          http://127.0.0.1:8090
手机/其它电脑:  http://10.21.231.58:8090
```

**用浏览器打开即可**（VNC 里用 Chrome，或手机连同一 WiFi）。

> ⚠️ 控制台**自己不起机器人节点**。要么先在另一个终端 `bash tools/boot.sh`，
> 要么用页面右上角的 **「▶ 启动整套」** 按钮（等价于跑 boot.sh，日志会流进页面）。

## 三、页面有什么

### 顶部状态条（一眼看全局）

| 显示 | 含义 |
|---|---|
| 急停 | `/mission/state.estop` |
| 定位 | `/localization/ok` |
| 机构 | `/rb_launcher/ok`（串口通不通） |
| 视觉 | `perception_ok` |
| CAN | `can0` 是否 UP（直接读系统，不经 ROS） |
| 雷达链路 | `enp114s0` carrier + IP（直接读系统） |
| 整套 | 是否由本页启动了 boot.sh |

### 左列 · 按钮

**起任务（一局）**
- 🔵 传球 PASS / 🟠 投篮 SHOOT / ⏹ 停止（IDLE）/ 🛑 急停
- 走 `/rb_mission/set_mission`；急停走 `tools/panic.sh`

**机构（拿球 / 发球）**
- 🚀 发射(0) / ⚡ 快发(1) / 🤲 运球(2) / 双运球(3) / 爪(4) / 滑道(5) / 停(7)
- 走 `/rb_launcher/launch`，对应 `kActionShoot=0, FastShoot=1, Dribble=2, DoubleDribble=3, PawlToggle=4, SlidewayToggle=5, KeepLoop=6, Stop=7`

**导航（仅 IDLE 下可用）**
- 🎯 去传球点 / 🎯 去投篮点 / 🏠 回出发点
- 坐标直接读 `mission.yaml` 的 `field.*`，不写死

**调试测试（整车脚本）**
- 🔍 **寻球 → 走到球前 50cm → 转身背对球**（= `tools/test_perimeter_ball.py --skip-perimeter`）
- 🏟 绕场一圈 → 寻球 → 转身（= 不加 `--skip-perimeter`）
- 🛞 底盘干跑自检（= `tools/test_chassis.py`，只解算不下发 CAN）
- ■ 停止调试脚本（SIGINT，脚本会先发零速）
- 脚本的 stdout **实时流进右下日志面板**（`TOOL` 青色）
- ⚠️ **寻球/绕场脚本会接管 `/cmd_vel`**（用 `--takeover` SIGTERM 掉任务节点），
  所以点了之后 `rb_mission` 就没了 —— 要恢复得按「▶ 启动整套」或重跑 boot.sh。
  点按钮时会弹确认框。

**点动**
- ↑↓←→ + 左转/右转，每次 0.4 秒后**自动归零**（不依赖松手）
- 底盘 200ms 超时是第二道保险

### 中列 · 画面

| 画面 | 来源 | 说明 |
|---|---|---|
| 📷 相机 | `/camera/image_raw/compressed`，没有就兜底用 `/camera/image_raw` | 真机是 compressed，离线仿真发原图 |
| 📡 雷达俯视图 | `/cloud_registered` + `/localization/pose` + `/perception/detections` | **以车为中心、车头固定朝上**；灰框=场地边界、◇=传球点/投篮点/篮筐/出发点、彩圈=球检测（带距离）、红箭头=车 |

> 俯视图上的球检测是按 `方位 = 车头yaw − bearing_rad` 反算的
> （`bearing_rad` 是相机约定**右正左负**，场地系是 y 朝左 —— 符号写反会镜像）。

### 右列 · 本轮进度（**最上面,现场最常看**）

起任务后实时显示**走到哪一步 / 卡在哪一步 / 每步花了多久**：

```
本轮进度（实时）                      SHOOT  已用 31.4s      动作 0/2
  ✓ 启动延迟   8.0s   SHOOT: 规则要求的 8.0s 启动延迟
  ● 找球      23.4s   接近 ball_volleyball bearing=-0.42 v=0.32      ← 进行中
  ○ 去动作区          待执行
  ○ 对准              待执行
  ○ 发射              待执行
  ○ 回位              待执行
```

* 阶段名是**中文**，`✓`已完成 / `●`进行中 / `○`待执行 / `✗`故障
* 每段**耗时**来自后端的阶段变迁记录；进行中那段的耗时是实时的
* **同一阶段内的说明文字也是实时的**（"对准 hoop 误差 +2.1°"会一直变）
* 起新任务时自动清空上一轮的时间线

### 右列 · 状态与日志

- **小车情况**：阶段/说明/任务/已用时/持球数/球类型/在传球区/在投篮线外/急停 —— 全部来自 `/mission/state`
- **子系统**：定位 / 机构 / 视觉 ok + 机构串口状态文本
- **位姿与数据链**：x,y / yaw / **里程计延迟**（>300ms 标红）/ **里程计 x**（>100m 标红判发散）/ 相机帧率 / 点云帧率
- **硬件链路**：CAN / 雷达网卡链路 / 雷达 ping / 相机设备 / 串口设备列表 / `/dev/R1_usb2ttl` 是否存在 /
  **关键节点数**（每个应该恰好 1 个）

> ⚠️ **重复节点检测**：`>1` 会在顶部弹红色警示。实测踩过：`kill -9` 掉 launch 后
> **子节点变孤儿**，再起一次就有两个 `mission_node` 同时发 `/mission/status`
> —— 症状是页面上的阶段**高频振荡**（START_DELAY ↔ SEEK_BALL 反复跳）。
> `boot.sh` 会清孤儿，但如果是手动起的栈就要靠这个检测。
> 清理：`bash tools/boot.sh`（它第 1 步就是清残留）
- **检测到的目标**：标签/置信/方位/距离
- **实时日志**：`/rosout`（所有节点的日志）+ boot.sh 的 stdout，可按"只看 WARN/ERROR"过滤
- **比赛轮次**：三轮的得分位置 + 每轮自动流程速查

## 五、踩过的坑（都在代码里注了）

| 坑 | 现象 | 处理 |
|---|---|---|
| **cv2.putText 不支持中文** | 所有中文变成 `?????` | 改用 PIL + `NotoSansCJK-Regular.ttc` 画字：先把图形用 cv2 画完，再一次性转 PIL 写文字 |
| `snapshot()` 里放原始字节 | `/api/state` 报 `Object of type bytes is not JSON serializable` | `cam` 出 JSON 前置 None，另给 `has_cam` |
| 相机流从 `snapshot()` 取图 | 画面永远空白 | 生成器**直接读** `bridge.state["cam"]`（snapshot 是给 JSON 用的） |
| 日志混元组和字典 | 排序时 `tuple indices must be integers` | 统一成 dict |
| 离线仿真发原图 | 相机流没画面 | 同时订阅 compressed 和 raw，谁先到用谁 |
| **`pkill -f` 自匹配** | 杀掉自己的 shell | 模式加 `[x]` **且**同一命令行里不能出现未加括号的名字 |
| `kill -9` launch → 子节点孤儿 | 再起一次就有两份节点，阶段乱跳 | `boot.sh` 会清；控制台加了「重复节点」检测 |
| 阶段内 detail 不刷新 | 页面只显示进入该阶段时那句话 | 同阶段的状态回调里回写时间线最后一条 |

## 六、安全

- 页面上的「急停」= 跑 `tools/panic.sh`（下发 estop + 零速 + 清多余进程）。
- **急停不替代手上的电源开关。**
- **绝不 `kill -9` 底盘节点** —— 一停止发 CAN，板子会因通信超时**锁死**，只能断电 10 秒重上电。
  要停就用急停按钮 / `set_mission IDLE`，让底盘继续发零速。
- 控制台是 Flask 开发服务器，**没有鉴权** —— 只在队内网络用，别暴露到公网。

## 七、自检

```bash
# 1) 控制台进程在不在
ss -ltn | grep 8090

# 2) 三个接口
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8090/
curl -s http://127.0.0.1:8090/api/state | head -c 300
curl -s --max-time 3 http://127.0.0.1:8090/api/lidar.mjpg | head -c 100

# 3) 无硬件时也能自检：起离线栈（合成图 + 假底盘），页面照样有数据

```
