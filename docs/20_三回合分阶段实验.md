# 三回合整轮及分阶段实验

依据 2026 修订规则 PDF 第 9、10 页；未改动的流程和几何按用户指定沿用 2025，第 7、10–13 页。2025 第 10 页传球、第 12 页投篮都明确：**A/B 是每个回合的起始区域**。因此不是第一回合结束后直接在场内开始第二回合；每次回合启动前重新放回本方出发区。一个回合内的两次取球/出球连续进行，不在两次动作间重新开一轮。

本版只做 A 区。车初始面向篮筐、平行中线。程序把启动时的实际位置/朝向对应到名义 S=(1.5,8.0,0)，不修改定位数据，也不要求雷达初始坐标恰好是零。物理上必须摆在 A 区：在其它位置点按钮仍会把该位置当作本轮起点，路线会整体偏移。

## 入口与参数

- 程序入口：`tools/test_perimeter_ball.py --route round1`、`--route round2`、`--route round3`。
- 路线实现：`tools/match_round_route.py`，`RoundRoute.execute()`；整轮使用 `tools/match_round_steps.py` 的 `execute_cycle()` 自动衔接三个阶段，与分阶段按钮共用动作。
- 场地坐标、行驶速度、搜索轨迹、区域后退距离、瞄准点和出球指令：`tools/match_rounds.json`。
- 前端：固定路线实验下面的“按轮完整测试”。主位置提供第1/2/3轮整轮按钮；第1轮默认比赛首球预装，自动处理两颗球并回位。机构总开关默认关闭，关闭时跳过所有机构指令并继续整个路线。三个阶段按钮及空场/单球实验收到折叠栏，整轮不会被辅助范围中的单球选项限制。靠近距离、速度、吸球开关在展开参数中，下次启动生效。

| 实验范围 | 实际执行 |
|---|---|
| `drive` 空场走路线 | 走本环节优先搜索轨迹→动作点→回本轮起点；不读取目标球、不吸球、不出球 |
| `collect` 默认 | 场上首球模式找一球、对正吸球、到动作点停车；预装模式第1回合送预装球；到动作点保持机构 |
| `cycle` 双次流程 | 第1回合按首球选择预装或场上取球、再取中线球；第2/3回合取两颗。每次到动作点放球/出球，最后回位。默认 `drop` 是放球联调；正式 `match` 出球必须先配置 `commands` 和 `aim` |

吸球已由用户确认成功：`STOP → ZERO → MOVE 1 90 5`；放球只发 `MOVE 1 0 5`，不追加STOP、ZERO。新三回合流程吸球成功后保持机构，到动作点的放球阶段才下发放球；原单次固定路线按钮保持原来行为。

代码运行结束只说明动作流程执行完成。当前没有可靠入仓、持球、实际出球反馈，所以不能凭脚本返回成功宣称获得比赛分数。空场路线模式须在球已清开的场地测试。

```bash
ssh user@10.21.231.58
cd /home/user/robocup_basketball_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
export ROS_DOMAIN_ID=2
# 先启动底盘、雷达定位、前后摄；路线命令会接管并停止旧任务节点。
python3 tools/test_perimeter_ball.py --route round2 --round-task pass --round-mode drive --takeover --yes
python3 tools/test_perimeter_ball.py --route round3 --round-task pass --round-mode collect --takeover --yes
# 投篮环节把 --round-task pass 改成 --round-task shoot；此时找排球。
```

两个命令是分别选择的实验，每次新开一回合重新摆车，不要当作连续脚本一起执行。分步入口为 `--round-step N`，例如 `--route round1 --round-task pass --round-step 1 --takeover --yes`；下一步保留其余参数，改成阶段2。后续阶段不重新摆车，不重置定位。

## 第一轮比赛完整流程：当前跳过机构

界面保持“比赛出球”、“首球预装”和机构开关关闭，点击“第1轮全自动（比赛流程）”；或在底盘、定位、前后摄已启动后执行：

```bash
cd /home/user/robocup_basketball_ws
bash tools/run_first_round.sh
```

程序不需要分步确认：静止5秒 → 右转90°入场 → 预装首球到传球区P=(3.6,4.5) → 第一次出球阶段 → 回中线观察走廊 → 预移到图右端X=4.4 → 向图左端寻找第二颗篮球 → 居中停车 → 转180° → 后摄横移对正 → 向球后退0.45m → 沿来路退出 → 回传球区 → 第二次出球阶段 → 回A区并恢复面向篮筐。两次处理球之间不重置本轮起点。

当前机构关闭：首球仍按预装流程走，所有吸球、传球、放球指令及视觉发射对准均跳过；第二球仍执行识别、横移对正和距离靠近。空机构执行完路线不代表球已收取或传出。普通移动0.25m/s，靠近0.08m/s；靠近期间不再要求YOLO。保持车实际位于A区、面向篮筐。

机构开关为CLI `--mechanism`/`--no-mechanism`（兼容旧的`--route-intake`/`--no-route-intake`）。`bash tools/run_first_round.sh --mechanism`开启全部机构动作；开启前必须填写真实传球发射指令和传球架瞄准点，缺失时启动前报错。配置在`tools/match_rounds.json`的`release.pass.commands/aim`。启动脚本默认关闭机构，不会因为串口未连接卡在出球阶段。

比赛完整路线与网页整轮按钮共用三个阶段实现；脚本开始后自主连续执行。网页与SSH是当前联调启动入口，现场本机开关可调用同一程序；规则中的正式比赛启动仍需接入本机物理开关。

## 每轮一键完整测试

```bash
bash tools/run_round_test.sh 1 pass
# 每次新开一轮先重新摆回A区；任选下一轮，不能把三条命令当连续启动。
bash tools/run_round_test.sh 2 pass
bash tools/run_round_test.sh 3 pass
```

通用实验脚本`run_round_test.sh`默认场上取首球和放球联调；第一轮比赛入口`run_first_round.sh`固定首球预装和比赛流程，机构默认关闭。第1轮按规则预装首球加`--round-first-ball preloaded`；投篮环节把`pass`改为`shoot`。整轮固定执行两次处理球和回位，阶段间无需确认；页面显示当前阶段和内部动作。失败停在未完成阶段，展开分阶段入口可续做；重新点击整轮会建立新起点，必须先把车摆回A区。`--no-route-intake`只测试运动并跳过机构指令，仍需要视觉寻找及对正。

目前正式传球/投篮发射指令尚未配置；默认MOVE 1 0 5是已验证的放球，不能替代真正发射动作。

## 第一回合分阶段

赛事规则模式请选择“首球预装”（CLI添加`--round-first-ball preloaded`），启动前预装一颗本环节目标球。实验界面及CLI默认“场上取首球”：第1阶段也从中线右端找球，方便复用固定路线联调。每轮最多3个阶段，阶段内部自动完成各动作，阶段结束停车：

1. **第一颗处理**：静止5秒→右转90°入场→带预装球到动作点→放球/正式出球。
2. **第二颗处理**：先到中线置球区图右端，再向图左端横扫→前摄居中停车→转180°→后摄横移对正→低速靠近到位→`STOP → ZERO → MOVE 1 90 5`铲球→等1秒→`MOVE 1 0 5`放下→动作点→放球/正式出球。第一回合不使用没有表列球的其它置球区兜底。
3. **回位**：返回A区，恢复面向篮筐。

对正、靠近、转运在同一个阶段中自动衔接。靠近期间不要求YOLO；阶段中途失败停车，重试会保留本轮起点、跳过已经完成的内部动作，靠近只补剩余位移，不重复整段距离。阶段控制状态暂存在 `/tmp/rb_match_rounds`，这不是比赛成功记录。已完成阶段1后，再点阶段1会重开本轮，重开前必须重新摆回起点；失败阶段请保持车的位置重试。

## 第二回合怎么走

1. S=(1.5,8.0)，朝 +X；静止5秒，右转90°。
2. 经 E=(1.5,6.8)，前进到 C=(1.5,4.8)，合计3.2米。
3. 前摄朝 −Y，保持 Y=4.8，先从 C 沿图 +X 预移2.9米至 R=(4.4,4.8)，到位后沿图 −X 搜索至 L=(0.6,4.8)，最多3.8米。每次中线搜索都从 R 向 L，不在回合内反向。预移途中只控制位姿，不触发视觉取球。
4. 目标到画面中心即停、转180°，后摄横移居中，然后向球低速后退。传球目标篮球，投篮目标排球。
5. 回到检测点，再沿已经走过的折线回 E。传球经 C 到 P=(3.6,4.5)；投篮经上侧 T=(6.4,6.8) 到 Q=(6.4,4.8)。取球靠近到位后自动抬起，等1秒放下；单次连续模式停在动作点；三阶段模式在本阶段内放球，然后停车。
6. 中线没有目标时，经 E、T 补扫三分弧。不能假定两队共享的2颗中线球一定留给本方。
7. `cycle` 模式放球联调或配置后的正式出球一次，再取第二颗、出球，最终经 E 回 S；不会在两次取球间回 S 重置路线。

2026 配置：中线目标/干扰=2/0；绿线=0/4，只有干扰；三分弧=3/2。不在绿线找目标球。

“右端/左端”按规则图定义：图 +X 朝篮筐，图 −X 朝左侧底线。场地14×7.5米，中线黄色置球段在 Y=3.75、X=0～5，长5米；不需要开到整场X=14。观察走廊两端各留0.6米，需实测确认整机包络和端点球视野。右转90°后，预移到图右端对应车体左移，向图左端搜索对应车体右移。

原“固定路线寻球”按钮也加入同样的预移和扫描方向。端点共用 `tools/match_rounds.json` 的 `middle.right_x=4.4`、`middle.left_x=0.6`，以 `start[0]=1.5` 计算预移量；`middle.y=4.8` 为三回合观察走廊。固定按钮前进距离仍可用 `--route-forward` 调整，预移和扫描可单独覆盖 `--route-scan-start-offset 2.9 --route-scan-distance 3.8`。偏移正值沿原出发朝向（图+X）；扫描固定朝图−X。新增动作并入现有取球阶段，每轮仍最多3阶段。固定按钮后摄对正后的后退距离现改为 **0.45米（45厘米，比原0.40米增加5厘米）**，前端或 `--route-scoop-distance` 可调整；三回合区域距离仍按本文件下表。

## 第三回合怎么走

第三回合中线没有球，直接 S→E→T，不执行中线横扫。

- **传球**：先扫三分弧（2篮球/2排球），没有篮球再扫内侧 X=9 置球线（3篮球/1排球）；取球后沿来路退出，回左侧 P 传球点。
- **投篮**：先扫内侧 X=9 置球线（3排球/0篮球），没有排球再扫三分弧（4排球/2篮球）；取球后退出，到 Q 投篮点。

三分弧搜索：车心以 (11,3.75) 为圆心、半径4.65米，按160°→170°→180°→190°→200°分段走，每段调整前摄朝向圆心。这个近侧弧段没有覆盖整条三分线；找不到换内侧搜索，不承诺扫描完整场地。

内侧搜索：车心 X=8.2，前摄朝 +X，沿 Y=6.2→1.3 平移。第二次扫描方向反过来。只写死观察路线，目标球的实际位置仍靠视觉发现。

第二、三回合均为3个阶段：①入场、取第1球、到动作点放球；②取第2球、到动作点放球；③回位。搜索、转身对正、靠近吸球和转运均在前两阶段内部自动完成。

`cycle` 执行两次取球/放球或正式出球指令后经 T、E 回 S。2026 已取消旧版“三分线外才能取球”的限制，可以进入三分区取球。

## 初始参数及接下来要调什么

| 参数 | 初值 | 调试内容 |
|---|---:|---|
| 普通行驶/横扫上限 | 0.25 m/s | 检查移动方向、里程和转向；末端随剩余距离减速 |
| 吸球靠近上限 | 0.08 m/s | 确认低速能克服底盘摩擦 |
| 中线起扫端点 | 图 X=4.4 m | `middle.right_x`，先移到这里再开始识别目标 |
| 中线结束端点 | 图 X=0.6 m | `middle.left_x`，默认从右向左扫3.8米 |
| 中线后退 | 0.45 m | 与固定路线一致；后摄对正后按位姿后退 |
| 三分弧后退 | 0.25 m | **试验初值，不是测距结论**；先测车心、摄像头、吸球口到球的关系 |
| 内侧线后退 | 0.15 m | **试验初值**；观察线离球更近，因此先用较短行程 |
| 前摄中心带 | ±4%画面宽度 | 是否停车及时，是否选错干扰球 |
| 后摄中心带 | ±2.5%，3个不同新帧 | 横移左右符号、对准稳定性 |

后退靠近只用定位位移，不继续要求 YOLO；YOLO 用于寻找目标和后摄横向对正。雷达提供位姿、里程计，未把未经确认的雷达球距当成精确后退距离。

后续依次补充：

1. **空场路线与取球距离**：每轮重新摆车，验收上下侧方向、通道宽度、180°转向以及三处实际吸球距离；确认铲球后放下能收住球、回撤不会掉球，动作点的放球能让球确实离开机构。
2. **机构出球和瞄准**：提供成功过的传球、投篮文本序列；写入 `release.pass/shoot.commands`。传球架坐标需实测填 `aim`，投篮默认篮筐坐标只是场地规划值。不能用吸球 `MOVE 1 90 5` 或停吸球 `MOVE 1 0 5` 冒充出球。
3. **入仓/出球反馈和目标关联**：确认球已入仓才转运，实际出球后才计一次。防止再次追同一颗未吸进的球；靠近有多颗同类球时保持同一个目标。
4. **干扰球避让**：本版保留用户当前的“避障关闭”。上侧 Y=6.8 是候选走廊，车身通过绿线端部、进入内侧时可能遇球；在带完整干扰球的场地跑之前，需要恢复并调好绕行，或修改已实测净空的通道。不能认为“绿线全是干扰球”就可以直接穿过它们。
5. **时长、动作点和回位**：Q 到篮筐约6.1米，需要射程校准，必要时改较近动作点。当前绕回通道与0.25速度可能超过120秒，尤其第三回合传球；实测后缩短往返，不能当作已经满足比赛时限。S中心到位还需确认全部承重轮在1×1米出发区。
6. **比赛启动**：网页用于实验。正式比赛按2026第7页改为本机开关触发，保留5–15秒静止延迟，完全自主运行；移动篮筐需实时识别瞄准。

本次添加可执行实验程序、9个阶段按钮（每轮3个）、连续运行入口和配置，没有启动机器人运动。放球联调不能替代评分要求的有效传球/投篮；自动发射与入仓/出球反馈仍待接入。


## 新模型与后续流程（2026-10-12）

模型随仓库发布：`src/rb_perception/models/ball_pillar_20261015.onnx`，SHA256见同目录`model.json`。实车前摄、后摄和寻球配置统一使用三类模型（篮球、排球、定位柱）；离线合成图配置保留颜色检测，其可选YOLO也映射这三类。配置中的模型路径相对配置文件解析，构建后自动安装模型，不依赖主机外部旧`/home/user/models/ball.onnx`。

| 阶段 | 使用的传感器 | 动作 |
| --- | --- | --- |
| 入场、搜索线预移、带球去动作点、回位 | 雷达FAST-LIO与场地位姿 | 按米数、坐标和角度走路线；普通平移最高0.25m/s |
| 搜索取球区域 | 前摄YOLO | 传球选篮球、投篮选排球；目标到中心立即停车 |
| 转180度后的横移对正 | 后摄YOLO | 仅左右微调，连续3个新帧满足中心容差后结束 |
| 对正后的靠近 | 雷达位姿位移 | 低速后退，不因球出画面而中止；固定路线总0.45m，三回合仍分别使用各区域`scoop_m` |
| 动作点瞄准 | 前摄YOLO定位柱 | 按名义目标转向后最多微调20度；只接受目标方向内唯一的新鲜柱，不用柱框高度推测距离 |
| 放球与回位 | 文本机构、雷达 | `MOVE 1 0 5`放球后沿路线返回；每轮最多3个阶段 |

定位柱参数位于`tools/match_rounds.json`的`pillar_alignment`：默认启用，置信度0.55、对准容差1.5度、稳定3个新帧、最长6秒、角速度最高0.15rad/s。`camera_yaw_offset_rad`和`launcher_yaw_offset_deg`分别表示相机、发射方向相对车头的水平偏角；目前均0，需实车核对。前摄的20度俯角不是水平偏角，不填到此处。

传球目标坐标仍需现场确定，`release.pass.aim=null`。放球联调先朝名义45度方向找唯一定位柱，这只是可修改的搜索朝向，不是规则给出的柱坐标。投篮名义目标仍为(12.425,3.75)，允许用相机对同方向的移动篮架柱修正瞄准。两者的正式出球`commands`仍空：已验证的吸球/放球指令不能当作已验证的传球/投篮发射指令。

放球联调若6秒内看不到唯一柱，会保留雷达设定的朝向继续联调。正式出球若启用了柱对准却没有对准，会停在动作点。多柱同时可见且无法识别身份时需要调整动作点、搜索朝向或目标配置，不能靠置信度猜柱。

固定地标与出球目标分开配置：`src/rb_localization/config/localization.yaml`保留初赛柱的规则标称坐标，但`enabled=false`，现场测量确认位置固定后才启用。决赛可移动篮架柱只用于瞄准，不能融合成固定地标纠正车的位置。定位更新拒绝旧框、重复框和歧义关联；它不刷新雷达真实数据时间戳。

## 自动铲球时序（2026-10-13）

固定路线默认勾选机构；后摄横移对正、转身后的向球后退距离完成后，底盘停车，
再发 `STOP`（等0.3秒）→ `ZERO`（等0.8秒）→ `MOVE 1 90 5`。
抬起指令发送成功后等1秒，仅发 `MOVE 1 0 5` 放下；不追加 STOP 或 ZERO。
整轮/分阶段共用此时序，取消机构勾选或传 `--no-mechanism` 时仅行驶、不发串口。
`run_first_round.sh` 仍保留原先的机构关闭默认；需要机构时使用 `--mechanism`，
正式传球/投篮仍须配置对应出球指令。这里验证的是指令顺序，实际收球效果须现场测试。
