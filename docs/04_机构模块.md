# 04 · 机构模块（rb_launcher）

弹射/夹爪/滑轨机构控制。对应包 `rb_launcher`。**⚠️ 尚未上车调通。**

---

## 1. 配置（`launcher.yaml`）

```yaml
port: "/dev/R1_usb2ttl"      # 串口设备（需补 udev 规则或改这里）
baud: 115200
send_rate_hz: 50.0           # 命令重复发送频率（下位机靠重复帧取最新值）
default_speed: 2800          # 发射转速（来自上一届 shoot_data.csv 常见值）
default_angle: 64            # 发射角度
auto_reconnect: true         # 串口打不开不崩溃，2 秒重试
```

---

## 2. 启动与动作测试

```bash
ros2 launch rb_launcher launcher.launch.py
ros2 topic echo /rb_launcher/ok          # 应为 true

# 从行程最小的动作开始
ros2 service call /rb_launcher/launch rb_msgs/srv/Launch "{action: 4, speed: 0, angle: 0}"    # 夹爪
ros2 service call /rb_launcher/launch rb_msgs/srv/Launch "{action: 5, speed: 0, angle: 0}"    # 滑轨
ros2 service call /rb_launcher/launch rb_msgs/srv/Launch "{action: 0, speed: 2800, angle: 64}" # 发射 ⚠️
ros2 service call /rb_launcher/launch rb_msgs/srv/Launch "{action: 7, speed: 0, angle: 0}"    # 停止
```

`action` 取值：`0=发射 1=快速发射 2=运球 3=两次运球 4=夹爪开关 5=滑轨开关 6=保持循环 7=停止`。

---

## 3. 串口准备

```bash
ls -l /dev/serial/by-id/                 # 找到 FTDI 设备名

```

## 5. 健壮性（已处理）

- 串口打不开**不崩溃**，打印日志后每 2 秒重试（原 `R1_server` 会 abort）。

## 串口设备名：自动回退 + 现场排查（2026-10-10 加）

**问题**：配置写 `/dev/R1_usb2ttl`，但本机 `/etc/udev/rules.d/usb2ttl_1.rules`
只生成 `/dev/usb2ttl`（还有 `pan_serial` / `argi_serial`）—— 名字对不上，
节点只会报"打开机构串口失败"，**拿球/发球完全不能用**，而且很难想到是名字问题。

**处理**：节点按候选列表找**第一个真实存在**的设备

```
① 配置里的 port（存在就优先，兼容现场自定义）
② fallback_ports 参数（默认 usb2ttl → ttyUSB0..3 → ttyACM0..1）
   相对 /dev 的名字或绝对路径都接受
```

日志会明说用了哪个（`INFO` 正常 / `WARN` 回退）：

```
[INFO] 机构串口已打开: /dev/usb2ttl @ 115200
[WARN] 配置的串口 /dev/R1_usb2ttl 不存在，已自动改用 /dev/usb2ttl @ 115200
```

**全都找不到**时（比如设备没插），不会崩，而是把**试过哪些名字**全列出来，
方便判断是"名字不对"还是"驱动没认到设备"：

```
[ERROR] 打开机构串口失败: /dev/R1_usb2ttl (open: No such file or directory)。
        已试过: /dev/R1_usb2ttl, /dev/usb2ttl, /dev/ttyUSB0, /dev/ttyUSB1,
        /dev/ttyUSB2, /dev/ttyUSB3, /dev/ttyACM0, /dev/ttyACM1。
        节点继续运行并每 2.0s 重连；请确认设备插好/驱动已加载，
        或补一条 udev 规则把它固定成 port 里的名字。
```

同时 `/rb_launcher/ok` 发 `false`，控制台顶部「机构」会标红。

### 要固定成 /dev/R1_usb2ttl（推荐，避免插错口）

```bash
# ① 把设备插上，看它的属性（记下 idVendor / serial / KERNELS）
udevadm info -a -n /dev/ttyUSB0 | grep -E "idVendor|idProduct|serial|KERNELS"

# ② 写规则（下面的值以上一步输出为准）
sudo tee /etc/udev/rules.d/99-r1-launcher.rules <<'RULE'
SUBSYSTEM=="tty", ATTRS{idVendor}=="1a86", ATTRS{serial}=="XXXXXXXX", \
  MODE:="0777", GROUP:="dialout", SYMLINK+="R1_usb2ttl"
RULE

# ③ 生效
sudo udevadm control --reload && sudo udevadm trigger
ls -l /dev/R1_usb2ttl        # 应指向 /dev/ttyUSBx
```

> 为什么按 `serial` 而不是 `KERNELS` 端口：换插口也不会变。
> 本机现有规则用的是 `KERNELS=="3-2.1"` 这种**物理端口**匹配，换口就失效。

单测：`src/rb_tests/test/test_launcher_serial.py::test_missing_configured_port_falls_back_to_candidate`
（虚拟 PTY，不碰真设备）。

### 协议逐字节验证（虚拟 PTY，不碰真机构）

`python3 tools/verify_launcher_protocol.py` —— 给机构节点一个虚拟串口，
抓它真正发出的帧并解码。结果**全过**：

| action | 名称 | 帧控制 | 帧数 | 说明 |
|---|---|---|---|---|
| 0 | SHOOT | `0x40` | 16 @20Hz | 默认 2800/64；显式传参 3333/77 也正确 |
| 1 | FAST_SHOOT | `0x41` | 16 | |
| 2 | DRIBBLE | `0x80` | 16 | |
| 3 | DOUBLE_DRIBBLE | `0x81` | 16 | |
| 4 | PAWL_TOGGLE | `0x20` | **1** | 开关类只发一帧（重复会再次翻转） |
| 5 | SLIDEWAY_TOGGLE | `0x10` | **1** | 同上 |
| 6 | KEEP_LOOP | `0x42` | 16 | |
| 7 | STOP | — | 0 | 只停重复发送，**不发帧**（不是物理急停） |

CRC32 全部正确；帧头 `+` 帧尾 `*`；11 字节 115200 8N1。

> ⚠️ **协议对 ≠ 机构动作对。** 运球/双运球的**物理行为在下位机固件里**，
> 本仓库不知道；`docs/04` 顶部也写着"尚未上车调通"。要靠在确保周围安全的前提下
> 用控制台按钮逐个试出来。
