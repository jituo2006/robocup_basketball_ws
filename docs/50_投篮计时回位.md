# 投篮整轮计时回位

120秒回合新增计时回位：默认至少预留35秒，最迟约第85秒请求退出任务；根据当前位置、当前速度、末段减速、E回正及余量估算回程更慢时，会提前请求。两次出球已完成则照常立即回位。计时使用单调时钟，从整轮执行入口开始，包含10秒启动等待，三个阶段之间不重置。

回位固定使用本轮开始时保存的坐标变换：当前位置→现有通道T→出场点E→恢复本轮初始朝向→初始点S。不是当前位置直奔S，也不在回位时重新建立起点。A/B沿用各自配置及原坐标变换，第三轮仍为先弧线、无球再内线。通道点与速度配置均未修改。

## 参数

`tools/match_rounds.json`：

```json
"timed_return": {
  "enabled": true,
  "tasks": ["shoot"],
  "round_duration_s": 120.0,
  "return_reserve_s": 35.0,
  "turn_reserve_s": 5.0,
  "margin_s": 5.0
}
```

默认只作用于投篮整轮 `cycle` 入口（包括整轮放球/关闭机构联调）；传球、单球 `collect`、空场 `drive` 和独立阶段按钮不启用整轮计时。每次重新启动整轮即新一轮；独立阶段入口不是比赛计时续跑工具。

回程预算采用当前实际通行/载球配置中较慢的速度；减速范围/速度优先读取当前Runner参数，包含终点2cm容差对应的P控制耗时。转向预留至少为配置值，并按实际角速度上限给出保守估计。1m/s只是此前讨论的未来方案，本次没有把速度升到1m/s。

以A侧Q=(10.195,0.903)为例，Q→T→E→S约10.20米；即使通行上限1m/s，当前末段减速下平移模型约17.2秒，再加回正和余量约27.3秒。现有0.65m/s载球上限下，平移约21.8秒，加回正和余量约31.9秒，因此先采用35秒预留。中线左端按现有通道回位更远，运行时动态计算。此模型没有计入真实加速度、打滑或阻塞，35秒需要现场测量校准，不能作为120秒内必定到位的保证。

## 切换行为

- 在移动、扫描、后摄等球/对正、靠近、等待以及机构服务等待中协作检查计时，由同一任务线程停止当前任务并进入回位，不增加另一条底盘控制线程。
- 启动新的取球机构时序前额外预留10.6秒；启动出球前额外预留该序列配置的等待时间。预算不足就直接请求回位，不先抬机构或发射。
- 已经开始的取球继续原有 `dji_stop→0.3s→dji_zero→0.3s→dji_move 1 90 5→5s→dji_move 1 0 5→5s→dji_stop`；已开始的出球按现有序列及等待完成复位，再切回位。不新增状态查询或其它机构指令。
- 机构写失败仍停车；计时已触发而机构服务结果未知时也停车，不凭未知机构状态开始行驶。明确定位故障或无有效位姿同样不启动回位。原有停止/故障处理不被计时回位绕过。
- 已经正常开始回位后不再用任务截止触发重启回位；仍受原有故障停车处理约束。
- 状态记录 `timed_return`、`returned_early`、`completed_releases` 和真正完成的阶段。提前回位不把未执行的两次取球/出球显示为已完成，也不自动确认规则得分或实物动作成功。

## 验证范围

专项测试覆盖A/B、三个回合、途中移动/扫描/后摄/靠近切入、初始坐标变换不变、E回正后进入S、慢速提前触发、机构固定时序完成、出球/载球状态恢复、服务等待故障、定位故障及关闭开关。全部为假时钟、假运动和假串口，不连接ROS或实车。

相关旧测试存在配置/接口变化造成的失败，需和未修改基线逐项对比；不能将其计为本次通过。上传GitHub不等于NUC部署，也不等于现场回位验收。
