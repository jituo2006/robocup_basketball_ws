## 4. 计分与计时不能混用

| 项目 | 传球 | 投篮 |
|---|---|---|
| 进场 | 5 | 5 |
| 每次动作位置分 | 传球区内 10，区外 5，未传出 0 | 投篮线外 10，线内 5，未投出 0 |
| 命中分 | 目标区 1/2/3：10/30/50，最多两次，压线算进 | 三分线内入篮 10、线外入篮 30；击中篮筐或板 5，未中 0 |
| 两次动作后回位 | 5，承重轮位于出发区内 | 15，同样需要承重轮位于区内 |
| 成功回位后的时间分 | 每剩余 5 s 得 1 分，最多 10 | 每剩余 2 s 得 1 分，最多 10 |
| 干扰球触碰 | 每次 -2 | 每次 -2 |

理想观测条件下的单回合例子：传球两次命中顶部圆环，进场/回位和时间满分，共 140；投篮两次三分线外命中，进场/回位和时间满分，共 110。例子不代表当前机器人已能取得这些分数。

积分赛按传球 30%、投篮 70%计算；决赛按竞赛积分 90%、资格认证 10%计算。积分赛出现影响晋级的同分可扩大晋级名额；决赛同分须加赛。PDF 没有清楚给出三个回合执行时间如何分配，不能把“每环节约 10 分钟（含准备/退场）”或当前工程 `300 s` 超时当成官方单回合时限。时间分输入应采用裁判确认的剩余时间。

## 5. 目前可执行的检查

```bash
cd /home/user/robocup_basketball_ws
python3 tools/check_match_rules.py
```

退出码：`0` 无缺口，`1` 仍有参赛实现/证据缺口，`2` 配置或读取错误。当前预期返回 `1`，这是审核结论，不是程序崩溃。该工具不会初始化 ROS 或向机器人发送指令。

原有工程调试入口现在明确使用：

```bash
python3 tools/match_run.py --practice --dry
```

`--practice` 不绕过 5–15 s、动作/持球上限和球种角色校验。`--dry` 不启动任务。实际调试启动仍须现场硬件与急停条件就绪，且按项目原流程处理节点和定位；本轮未启动真实机器人。

`score_estimate=-1` 是本接口的“未知”标记，不是裁判扣分。观测后计分可以调用 `rb_mission.match_rules.score_round`；它不包含官方当轮判零、重新出发等裁判裁决，也不自动判定哪些发射或进球有效。

## 6. 后续优先级与验收边界

1. **P0：拿到今年场地图/现场确认**，测量出发区、动作区、边界线、篮筐和承重轮轮廓；完善运行越界保护与回位判定。
2. **P0：硬件断动力急停和真实持球计数**，补球种/出球信号、失效处理和自主风险拍停；确认初始预装球解释。
3. **P0：低速避障验证后启用**，使用两类实际比赛用球，验证测距、方向、停车距离；不直接开启未经验证的旧参数。
4. **P1：移动篮筐闭环与发射模型**，验证追踪时延、停稳对准、距离-转速/角度关系。
5. **P1：按三个回合球数做离线与实车场景测试**，然后测试整回合完成、回位和相应剩余时间。
6. **材料与现场流程**：比赛前 60 日提交用球品牌/型号/颜色照片（具体日期以群通知为准）；比赛前 30 日提交资格认证 PDF；准备助理裁判、原创性及库复用说明、尺寸重量与急停证据。

本轮软件测试与规则审核不能代替硬件检验、整车安全验收、裁判解释和真实得分验证。已有库的复用关系可以记录在原创性/合作开发材料中，无需完全复刻旧机器人。
