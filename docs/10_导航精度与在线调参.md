# 10 · 导航精度与在线调参

本轮改动解决重复坐标旋转、旧定位继续驱动车辆、穿过到位范围就提前结束的问题。默认参数是调试起点，实际停止距离、轮子打滑和定位噪声仍需实体实验确认。

## 1. 控制接口

- `/cmd_vel` 始终是车体坐标：x 向前、y 向左、正角速度逆时针。任务节点把场地误差转成车体速度一次，底盘直接解算四轮转速，不再按 `/odom` 的 yaw 旋转第二次。外部速度发布者也必须遵守此约定。
- 定位输入优先使用正规四元数；仅全零四元数兼容旧的 `position.z=yaw` 格式。合法单位四元数表示 yaw=0，不能把雷达高度误当 yaw。
- `/localization/pose.header.stamp` 保留最近被接受的真实位置输入时间戳，定时发布不会刷新它。零时间戳、未来、过期、倒序和同一来源重复时间戳的输入不会作为新测量。
- `/localization/ok` 同时要求位置输入新鲜和协方差达标。只有视觉方位角更新不能让已经失联的里程计重新有效。输入和节点必须使用一致的 ROS 时钟。
- 任务节点同时检查 pose 源时间戳和 ok 消息接收间隔。失效立即发布零速，保留目标等待恢复，重新累计停稳时间；原阶段的导航等待上限仍有效，超时转 FAULT。更换目标也清除旧确认状态。

## 2. 到位判据

GOTO、去动作区、回起点共用判据：

1. 距离进入 0.10m 时停止平移，进入确认阶段。
2. 在距离 ≤0.10m、实测平移速度 ≤0.03m/s、实测角速度 ≤0.05rad/s 的条件下，连续新测量保持 0.5s 才完成。要求朝向的 GOTO 还需 yaw 误差 ≤0.08rad；其他导航不要求目标朝向，但仍需停止旋转。
3. 漂到 0.10–0.12m 的滞回带内仍需低速修正；超过 0.12m 退出确认，重新接近。首次进入范围后修正速度上限为 0.08m/s，视觉避障叠加后也保持此上限。
4. 从首次进入到位范围起，5s 内无法停稳则停车并进入 FAULT；漂出范围不会不断重置这项期限。

实测速度来自约 0.15s 窗口内不同源时间戳的位姿差分，并非用“发了零速度”代替“已停稳”。同一旧位姿被重复发布不能累计确认时间。该估计仍受定位噪声和窗口内运动影响，应与实车停车表现一起调参。

## 3. 在线参数接口

以下名称均为 ROS 参数，可通过 `ros2 param list/get/set` 查看和修改；启动 YAML 的段名与参数前缀一致。

| 节点 | 参数 | 默认 | 含义/单位 |
|---|---|---:|---|
| `/rb_mission` | `limits.max_linear` | 0.40 | 平移上限 m/s |
| `/rb_mission` | `limits.max_angular` | 0.80 | 转向上限 rad/s |
| `/rb_mission` | `limits.kp_linear` | 1.5 | 位置控制增益 |
| `/rb_mission` | `limits.kp_yaw` | 2.0 | 朝向控制增益 |
| `/rb_mission` | `limits.position_tolerance` | 0.10 | 完成距离阈值 m |
| `/rb_mission` | `limits.yaw_tolerance` | 0.08 | 朝向误差阈值 rad |
| `/rb_mission` | `navigation.pose_timeout_s` | 0.5 | 位姿最大源年龄 s |
| `/rb_mission` | `navigation.loc_ok_timeout_s` | 0.5 | ok 消息最大接收间隔 s |
| `/rb_mission` | `navigation.velocity_window_s` | 0.15 | 差分估速窗口 s |
| `/rb_mission` | `navigation.exit_margin_m` | 0.02 | 确认退出距离余量 m |
| `/rb_mission` | `navigation.linear_speed_tolerance` | 0.03 | 停稳平移速度 m/s |
| `/rb_mission` | `navigation.angular_speed_tolerance` | 0.05 | 停稳角速度 rad/s |
| `/rb_mission` | `navigation.settle_time_s` | 0.5 | 连续停稳时长 s |
| `/rb_mission` | `navigation.settle_timeout_s` | 5.0 | 首次进范围后的确认期限 s |
| `/rb_mission` | `navigation.correction_max_linear` | 0.08 | 位置修正速度上限 m/s |
| `/rb_localization` | `source_timeout_s` | 0.5 | 真实位置输入最大年龄 s；YAML 为 `sources.source_timeout_s` |

```bash
ros2 param set /rb_mission limits.position_tolerance 0.10
ros2 param set /rb_mission navigation.correction_max_linear 0.08
ros2 param set /rb_mission navigation.settle_time_s 0.5
ros2 param set /rb_localization source_timeout_s 0.5
```

参数必须有限且为正，`exit_margin_m` 可为零；估速窗口必须小于 pose 超时，停稳时长必须小于确认期限。关联参数一起变化时应使用 ROS 的原子参数设置接口，或按保持约束成立的顺序逐个设置。

任务参数通过验证并被 ROS 接受后，在下一控制周期应用，同时发送零速并重建速度估计/到位确认，保留目标。只做参数校验的回调没有控制副作用，其他回调拒绝请求也不会提前改变行为。启动可用 ROS 参数覆盖 YAML 默认值；在线值不会自动写回 YAML。确认有效后保存至配置文件，供下次启动使用。`config_file` 的变更需要重启。场地、机构、避障等其余 YAML 项本轮没有开放动态接口。

## 4. 验证与实体调试安排

本地 Mac 验证：91 项 Python 检查通过（纯逻辑和真实节点方法的消息边界替身），独立 C++ 运动学检查通过，覆盖非零车头角、停稳、过冲、旧定位、参数校验和轮速。替身检查没有启动 ROS/DDS；完整 ROS 构建、实际话题和实车效果尚未验证。

机器人更新后先构建并运行包测试：

```bash
colcon build --symlink-install --packages-up-to rb_chassis rb_localization rb_mission rb_tests
source install/setup.bash
colcon test --packages-select rb_chassis rb_localization rb_mission
colcon test-result --verbose
```

实体实验按以下顺序，每次记录配置、实际距离、最终误差、峰值过冲、确认耗时和定位年龄；建议同时录制 `/cmd_vel`、`/Odometry`、`/localization/pose`、`/localization/ok`、`/mission/status`。

| 顺序 | 实验 | 验证目的 |
|---|---|---|
| 1 | 架空低速检查前进、横移、旋转；随后车头分别朝 0°、90°、180°，点击同一场地方向 | 轮序/电机方向正确、无二次坐标旋转 |
| 2 | 静止记录至少 30s，再低速走 1m 和旋转 90° | 估计定位噪声、距离比例和朝向误差，复核轮径及雷达安装偏移 |
| 3 | 从 0.10m/s 起，做前后/左右 0.5m、1m、2m，每组至少 5 次 | 看停止距离和过冲，先调速度/增益，再调容差及停稳阈值 |
| 4 | 到点后轻微漂移；增加 GOTO 朝向要求 | 必须停稳才完成，漂移能低速修正，超时能停车 |
| 5 | 停止位姿输入、重复旧时间戳、停止 ok 发布，再恢复 | 定位失效停车；恢复重新确认，失联超时进入 FAULT |
| 6 | 在线修改一个参数，再重复相同距离/方向实验 | 验证接口生效，并选定可保存的参数 |

定位超时应结合实际输入频率和延迟设置；不能通过放宽超时掩盖定位断流。物理误差以卷尺/地面标记实测，不能只用定位自身的目标误差宣称精度达标。
