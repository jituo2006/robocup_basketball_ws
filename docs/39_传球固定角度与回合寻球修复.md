# 传球固定角度与回合寻球修复

2026-10-15。适用于三个回合的传球路线 `round1/round2/round3`。

## 寻球中断原因

`RoundRoute` 创建时把回合编号存为 `self.round`，最新搜索调用却读取不存在的 `self.round_number`，导致已经走到搜索入口后发生 `AttributeError` 并停车。现统一读取 `self.round`，按回合配置选择中线方向。

第1回合仍先右后左；第2回合先左后右。三分弧、内线的第二球扫描反向规则保持。日志、页面提示与测试同步到当前方向和传球点 `(3.55,4.95)`。

## 当前传球方式

`aim` 是名义目标点坐标，不是雷达定位函数。原逻辑用当前位置与该坐标计算出球朝向，并可继续用前摄定位柱微调。现在传球采用固定角度：

```json
"aim_mode": "fixed",
"aim": null,
"search_heading_deg": 49.0
```

配置位于 `tools/match_rounds.json` 的 `release.pass`。角度相对本回合启动朝向，按原坐标系正方向旋转；49度不是相对到达传球点时朝向再追加49度。每次传球都先通过原来的旋转控制到达目标角度，再执行 `vesc_status`、`vesc_home`、`vesc_shoot 3`。到点、转向、串口任一失败均停止后续动作。失败后从发射阶段重试时会恢复传球点和配置朝向。

固定模式不要求 `aim`，不调用前摄对柱微调。雷达/里程计的行驶、转角控制、定位新鲜度、进展监测、急停与回位仍使用原逻辑。前摄找球、后摄横移对球仍执行。

若以后恢复坐标瞄准，把 `aim_mode` 改成 `target` 并填写 `aim`；原来的前摄对柱开关仍由 `pillar_alignment.enabled` 控制。投篮仍使用原目标坐标和视觉对柱流程。

## 运行入口

`run_first_round.sh`、`run_round2.sh`、`run_round3.sh` 默认关闭机构。使用 `--mechanism` 启用机构后，三个入口均接受上述固定角度配置。控制台的就绪判断同步此规则。

路线耗时、搜索覆盖与车体包络仍按原配置，尚未通过实车验收。固定角度由操作者调参确认；程序响应成功不能证明入仓、发射或命中。旧文档和2026-10-15审计记录描述的是对应历史版本。

## 验证

新增覆盖三个回合两次传球、起始坐标变换、49度及负角度调参、到角度失败不发射、串口失败后恢复朝向、后备搜索及无球停车的离线测试，并检验第2/3回合 shell 启动校验。所有测试均使用模拟对象，不发布机器人指令。
