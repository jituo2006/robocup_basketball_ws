### 2.1 怎么量这个坐标 —— 让车当尺子

场地坐标系是"开机时车摆在哪"定义的，用卷尺直接量很别扭。改用**反算**：

```
柱子位置 = 车的位置 + 距离 × (yaw + 相机偏置 − bearing 的方向)
```

车的位姿来自 `/localization/pose`，距离与方位角来自 `/perception/detections`
（pillar 的距离是按柱子的**实际宽度**做单目测距）。

```bash
# ① 先看看测出来的稳不稳（不动配置）
python3 tools/measure_landmark.py

# ② 满意了再写回配置（自动备份 + 质量门限）
python3 tools/measure_landmark.py --write
```

**质量门限**（不达标会拒绝写入，避免把噪声写进配置）：
样本数 ≥ 10、坐标抖动 ≤ 0.15m。

**前提与注意**：

| # | 事项 |
|---|---|
| 1 | 雷达 + FAST-LIO + `rb_localization` 都要在跑 |
| 2 | 柱子在相机视野内、被检出为 `pillar`（先 `tools/view_camera.py` 确认） |
| 3 | `pillar` 检测器的 `real_width_m` 必须等于柱子**真实宽度**（默认 0.20m），否则距离按比例偏 —— 这是唯一的系统误差来源 |
| 4 | ⚠️ **测量时车不能动**，"车当尺子"的基准一变结果就废 |
| 5 | 距离越远，单目测距的相对误差越大 → 柱子**放在 1.5~3m 处**测最准 |

**符号**：反算复用 `rb_localization.ekf2d.camera_bearing_to_world()`，
与 EKF 同一套约定（有单测锁住），**不要在工具里另写一遍公式**（见 `02_感知模块` §2.5）。

**验证是否生效**：重启定位后应看到限频日志

```
定位柱更新: 地标(3.50,2.00) 观测方位=+12.3° 累计=57
```

### 2.2 ⚠️ 雷达安装平移偏移：方向是反的，而且按**车体 yaw** 旋转

```yaml
sensor_to_base_x: -0.30    # 「从雷指向车体旋转中心」的向量，不是"雷达在哪"
sensor_to_base_y: 0.0
```

**两个坑，都踩过：**

#### 坑 1：方向是反的

`sensor_to_base` 是「**从雷指向车体中心**」的向量：

| 物理事实 | 应填 |
|---|---|
| 雷达在车体中心**前方** 30cm | `sensor_to_base_x: -0.30` ← **负号！** |
| 雷达在车体中心**后方** 30cm | `sensor_to_base_x: +0.30` |

#### 坑 2：必须按**车体 yaw** 旋转，不是雷达 yaw

```
byaw = oyaw + s2b_yaw                      # 先算车体朝向
base = sensor + R(byaw) · (s2b_x, s2b_y)   # 用【车体】yaw 转
```

安装偏移物理上固定在**车体系**；而雷达可能装得转了角度。
**本车 `sensor_to_base_yaw = -85°`(几乎 90°)** —— 若错用雷达 yaw 旋转，
"前 30cm" 会变成 "侧 30cm"：

| | base 相对 sensor | 车体系里的真实方向 |
|---|---|---|
| 错用雷达 yaw | (+0.300, 0.000) | **侧偏 0.3m** |
| 按车体 yaw(已修) | (-0.026, +0.299) 长 0.300 | 车体正后方 ✓ |

**症状**：RViz 里位姿箭头跑到车体的**左上角**（而不是落在旋转中心）。

**怎么验证修好了**：

```bash
# 把车【原地转 180°】，看 RViz 里箭头会不会跟着甩出去
#   修好：箭头基本留在原地（转的是车，不是中心）
#   没修：箭头会绕着画一个半径 0.3m 的圈
```

> 代码抽成了 `ekf2d.sensor_to_base_xy()`，有 4 条单测锁住（见
> `test_ekf2d.py::test_sensor_to_base_uses_body_yaw_not_sensor_yaw` 等）。

### 2.3 ⚠️ 里程计 twist 是 **world 系**，不是车体系

`Ekf2D.predict()` 的入参约定是**车体系**速度（内部会再按 yaw 旋转一次）。
但 **FAST-LIO 的 `/Odometry.twist` 是世界(camera_init)系速度**：

```cpp
// ~/lidar_360/fast_prop_ws/.../include/common_lib.h:147
V3D vel_end;   // the estimated velocity at the end lidar point (world frame)
```
```cpp
// laserMapping.cpp:981
imu_predicter.get_state(P, q, V);
odom.twist.twist.linear.x = V.x();
odom.header.frame_id = "camera_init";
```

**直接把 world 系速度喂进 predict = 多转了一次 yaw**，预测方向完全错，
表现为**车一运动定位就发飘**（静止时看不出来，因为 twist≈0）。

正确做法（`ekf2d.world_vel_to_body()`，有 4 条单测）：

```
byaw   = wrap_pi(雷达yaw + sensor_to_base_yaw)     # 车体在 odom 系的朝向
v_body = R(−byaw) · v_world
```

> ⚠️ 换里程计来源时要注意：**底盘轮式里程计**的 twist 通常是 body 系，
> 而 FAST-LIO 是 world 系 —— 两者不能套同一套代码。

**排查速查**:`/livox/lidar` 有数据但 `/Odometry` 没有 → 看 FAST-LIO 的 launch 日志:
```
[WARNING] Parameter file path is not a file: ~/...     ← ~ 没展开
[ERROR]   [fastlio_mapping-1]: process has died [exit code -11]   ← 段错误
```

### 4.1 ⚠️ FAST-LIO 跟丢会发散，只能重启

实测踩过：`/Odometry` 的 x 在几秒内从 0.1 涨到 **200+**。日志里刷 `No Effective Points!`
—— 意思是**点云里没有可用于配准的结构**，FAST-LIO 只剩 IMU 积分，必然发散。

| 原因 | 表现 |
|---|---|
| 移动太快 | 地图和当前扫描对不上 |
| 贴墙 / 正对空白墙 | 有效点太少 |
| 空旷环境、视野里没结构 | 同上 |

**恢复**:发散的里程计救不回来，**必须重启 FAST-LIO**（重新初始化坐标系）。
对策：**推车/开车别太快**，并保证雷达视野里有墙/家具这类结构。

### 4.2 ⚠️ 雷达安装朝向必须标定（`sensor_to_base_yaw_deg`）

**这是最容易漏、症状最迷惑的一项。**

配置注释说"旋转量由 start_pose.yaw − 首帧yaw 自动算出" —— 但那只解决
**开机时车没摆正**。FAST-LIO 的坐标系在**初始化瞬间**建立，**首帧 yaw 恒为 0**，
所以自动算出的旋转里**不包含雷达装歪的角度**，必须显式补偿。

**漏标的症状**（极易误判成"雷达不准"）：
```
沿车头推 1m  →  定位的 x 只变 0.03
但 /Odometry 的位移幅度是对的（~0.85m），只是全跑到 y 方向去了
```

**标定步骤：**

```bash
# 1. 起雷达驱动 + FAST-LIO + 定位
# 2. 把车沿【车头方向】直线慢推 1m（慢！走直线！）
# 3. 看 /localization/pose 的位移方向：
ros2 topic echo /localization/pose --field pose.pose.position
```

| 结果 | 结论 |
|---|---|
| x 增加 ~1.0 | ✅ 已正确，不用改 |
| 主要变的是 y | ❌ 雷达装歪了，需要补偿 |

```yaml
# 补偿量 = 车体方向 − 雷达系方向
# 本车实测：把车【向后退 1m】，雷达里程计位移方向是 +94.7°
#   车体后方在车体系是 180°
#   → 需要补偿 180 − 94.7 ≈ 85°
#   → 按代码约定 theta = start_pose.yaw − 首帧yaw − s2b_yaw
#      验证：s2b_yaw=-90 → theta=+90，(Δx,Δy)=(-0.08,+1.00) 旋转后 = (-1.00,-0.08) ✅ 正是后退
sensor_to_base_yaw_deg: -85.0
```

标定后复验：推 1m，定位 x 应从 1.0 → ~2.0（实测 +1.065m ✅）。

雷达点云是大消息，若上不去先怀疑 7MB/s 吞吐瓶颈（见 `01_相机模块` §3）。

## 7. 相机安装角标定

### 7.1 俯角（影响能同时看到球和篮筐的范围）

本车相机 **FOV 与水平成 30° 朝下**。垂直 FOV 约 ±24°，所以：

| 项 | 值 |
|---|---|
| 画面上缘 | 水平线下方约 6° |
| 画面下缘 | 水平线下方约 54° |
| 相机高 0.5m 时能看到最近地面 | ~0.36 m |

**取舍**：俯角越大越能看清近处的球，但越看不到高处的篮筐。30° 是"先保球"的选择。
若发现对准篮筐时筐进不了画面，可以适当减小俯角（但要确认球还在画面里）。

### 7.2 方位角偏置（`camera_yaw_offset_rad`）


`camera_yaw_offset_rad` = 相机光轴与车体前进方向夹角。

标法：把车摆正对着一个已知方位目标，看 `bearing_rad` 与理论值差多少，填差多少。
