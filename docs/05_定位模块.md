## 2. 配置（`localization.yaml`）

```yaml
sources:
  odom_topic: "/Odometry"        # 雷达 FAST-LIO 位姿（注意大写 O，不是底盘 /odom）
  use_odom_pose_as_abs: true
  abs_pose_topic: ""             # 留空 = 不用外部绝对位姿
  detections_topic: "/perception/detections"
  camera_yaw_offset_rad: 0.0     # 相机光轴与车体前进方向夹角，要标定
output:
  pose_topic: "/localization/pose"
  ok_topic: "/localization/ok"
```

⚠️ **`landmarks` 当前为空** → 视觉方位角更新**不会生效**（EKF 收不到观测）。
需按本轮定位柱实际坐标填：

```yaml
landmarks:                       # 定位柱在场地坐标系的坐标
  - {x: 3.5, y: 2.0}
```

## 4. 雷达接入（FAST-LIO）

```bash
python3 tools/check_lidar_net.py --ping    # 雷达网络是否就绪
# 需主机网卡配置 192.168.1.x，见 ~/lidar_360 的工作空间说明
```

**手动起雷达（分两段，方便排错）：**

```bash
# ① 雷达驱动
source ~/lidar_360/ws_livox/install/setup.bash
ros2 launch livox_ros_driver2 msg_MID360_launch.py
ros2 topic hz /livox/lidar        # 应 ~10 Hz；再查 /livox/imu 应 ~200 Hz

# ② FAST-LIO
source /home/user/lidar_360/ws_livox/install/setup.bash
source /home/user/lidar_360/fast_prop_ws/install/setup.bash
ros2 launch fast_lio mapping.launch.py \
  config_path:=/home/user/lidar_360/fast_prop_ws/src/FAST_LIO_WITH_PROPAGATE/config \
  config_file:=mid360.yaml rviz:=false
ros2 topic hz /Odometry           # 应 ~10 Hz
```

> ⚠️ **`config_path:=` 后面千万别用 `~`。** bash 只在**词首**展开波浪号,
> `config_path:=~/xxx` 会原样传字符串 `~/xxx` → FAST-LIO 当成不存在的路径 →
> **读不到配置直接段错误崩溃**(`exit code -11`),表现为"雷达有点云但 `/Odometry` 一直没数据"。
> 用**绝对路径**或 `config_path:=$HOME/...`。
> （`rb_bringup/launch/bringup_lidar_vision.launch.py` 里已是绝对路径,没这个问题。）

**排查速查**:`/livox/lidar` 有数据但 `/Odometry` 没有 → 看 FAST-LIO 的 launch 日志:
```
[WARNING] Parameter file path is not a file: ~/...     ← ~ 没展开
[ERROR]   [fastlio_mapping-1]: process has died [exit code -11]   ← 段错误
```

### 4.1 ⚠️ FAST-LIO 跟丢会发散，只能重启

实测踩过：`/Odometry` 的 x 在几秒内从 0.1 涨到 **200+**。日志里刷 `No Effective Points!`
—— 意思是**点云里没有可用于配准的结构**，FAST-LIO 只剩 IMU 积分，必然发散。

| 原因 | 表现 |
|---|---|
| 移动太快 | 地图和当前扫描对不上 |
| 贴墙 / 正对空白墙 | 有效点太少 |
| 空旷环境、视野里没结构 | 同上 |

**恢复**:发散的里程计救不回来，**必须重启 FAST-LIO**（重新初始化坐标系）。
对策：**推车/开车别太快**，并保证雷达视野里有墙/家具这类结构。

### 4.2 ⚠️ 雷达安装朝向必须标定（`sensor_to_base_yaw_deg`）

**这是最容易漏、症状最迷惑的一项。**

配置注释说"旋转量由 start_pose.yaw − 首帧yaw 自动算出" —— 但那只解决
**开机时车没摆正**。FAST-LIO 的坐标系在**初始化瞬间**建立，**首帧 yaw 恒为 0**，
所以自动算出的旋转里**不包含雷达装歪的角度**，必须显式补偿。

**漏标的症状**（极易误判成"雷达不准"）：
```
沿车头推 1m  →  定位的 x 只变 0.03
但 /Odometry 的位移幅度是对的（~0.85m），只是全跑到 y 方向去了
```

**标定步骤：**

```bash
# 1. 起雷达驱动 + FAST-LIO + 定位
# 2. 把车沿【车头方向】直线慢推 1m（慢！走直线！）
# 3. 看 /localization/pose 的位移方向：
ros2 topic echo /localization/pose --field pose.pose.position
```

| 结果 | 结论 |
|---|---|
| x 增加 ~1.0 | ✅ 已正确，不用改 |
| 主要变的是 y | ❌ 雷达装歪了，需要补偿 |

```yaml
# 补偿量 = 车体方向 − 雷达系方向
# 本车实测：把车【向后退 1m】，雷达里程计位移方向是 +94.7°
#   车体后方在车体系是 180°
#   → 需要补偿 180 − 94.7 ≈ 85°
#   → 按代码约定 theta = start_pose.yaw − 首帧yaw − s2b_yaw
#      验证：s2b_yaw=-90 → theta=+90，(Δx,Δy)=(-0.08,+1.00) 旋转后 = (-1.00,-0.08) ✅ 正是后退
sensor_to_base_yaw_deg: -85.0
```

标定后复验：推 1m，定位 x 应从 1.0 → ~2.0（实测 +1.065m ✅）。

雷达点云是大消息，若上不去先怀疑 7MB/s 吞吐瓶颈（见 `01_相机模块` §3）。

## 6. 相机方位角偏置标定

`camera_yaw_offset_rad` = 相机光轴与车体前进方向夹角。

标法：把车摆正对着一个已知方位目标，看 `bearing_rad` 与理论值差多少，填差多少。
