# 09 · 赛场运行手册（打印带着）

> 一页纸版。每一步都有**验收标准**，不达标就别往下走。
> 排查细节见 [07 整车联调与排查](07_整车联调与排查.md)。

---

## 一、到场后做一次（赛前，约 60 分钟）

### 1. 硬件（20 分钟）

```
□ 雷达：网线插到 enp114s0，雷达**上电**
□ 电机板：**断电 10 秒再上电**（清"通信超时"锁存）
□ 相机：USB 插好
□ 机构串口：（如有）插好
```

```bash
# 验证雷达网络
ping -c 2 192.168.1.138
```

### 2. 整车跑起来（10 分钟）

```bash
# 合上总开关（雷达 + 电机板 + 相机一起上电）
rbws
bash tools/boot.sh          # 前台，日志直接刷屏；保持这个终端开着
```

**验收（看到这三句）:**
```
底盘已使能 4 个电机（board_id=1）
mission 就绪: 场地 14.0x7.5 m
livox/lidar publish use livox custom format
```

另开终端：
```bash
rbws
bash tools/check_ready.sh
```
**验收：全绿**（CAN / 雷达 / IMU / 点云 / 里程计 / 定位 / 未发散）。

### 3. 量场地，填 `field`（20 分钟）

`src/rb_mission/config/mission.yaml` 的 `field:` 段。**必须实测：**

| 项 | 说明 |
|---|---|
| `hoop: {x, y}` | 篮筐中心在场地坐标下的位置 |
| `three_point_center` / `three_point_radius_m` | 三分线圆心与半径 |
| `pass_zone.polygon` | 传球区四边形（4 个角点） |
| `shoot_zone_target` / `pass_zone_target` | 站位目标点 |
| `home: {x, y}` | 回位点 |

> ⚠️ **填错会让 `_zone_ok()` 误判"位置不合规"→ 车站着不动且不报错。**
> 来不及量就把 `limits.require_zone_compliance` 设成 `false`（宁可拿低分也不要 0 分）。

改完**必须重启 mission 节点**（`bash tools/boot.sh`）。

### 4. 确定摆车位，填 `start_pose`（5 分钟）

1. 在发车区**地上贴胶带**做出车的四轮位置 + 车头方向
2. 卷尺量出这个位置在场地坐标下的 `(x, y, yaw)`
3. 填进 `src/rb_localization/config/localization.yaml`：
   ```yaml
   start_pose:
     x: <实测>
     y: <实测>
     yaw: 0.0      # 车头朝场地 +x = 0
   ```

### 5. 试跑验证（10 分钟，**最重要**）

```
□ 键盘遥控 6 方向对（前进/后退/左移/右移/左转/右转）
   python3 tools/teleop_chassis.py --drive
□ 推车走一圈，RViz 箭头同步、方向对
□ 点一个 1~2m 的目标，车准确停在点上（连点 3~5 次）
```

## 二、每局开赛前（3 分钟，照着做）

```
① 把车摆到地上的标记处（四轮 + 车头方向都要对上）
② 合总开关（雷达 + 电机板 + 相机）
③ bash tools/boot.sh                      ← 等 30 秒
④ bash tools/check_ready.sh               ← 必须全绿
⑤ 看 RViz：箭头位置对着标记量一下（误差 < 20cm 可接受）
⑥ 准备起任务
```

**急停预案：另开一个终端，`bash tools/panic.sh` 已就绪（先别按）。**

---

## 三、起任务（比赛开始）

### 推荐：一局一键

```bash
rbws
python3 tools/match_run.py                  # 投篮（默认）
python3 tools/match_run.py --mission PASS   # 传球
python3 tools/match_run.py --dry            # 只做检查，不起任务
```

它会依次做四件事，任何一步不过都会**停下来并告诉你怎么办**：

```
[1/4] 检查整套软件        （驱动/FAST-LIO/定位/底盘/任务 都在跑吗）
[2/4] 数据链就绪检查      （跑 check_ready.sh：CAN/雷达/IMU/点云/里程计/定位/未发散）
[3/4] 检查车还在出发点吗  （当前位姿 vs start_pose，偏差 >0.5m 会警告）
[4/4] 起任务并实时打印阶段（起之前要你按 y 确认）
```

### 或者手动两步

```bash
# 投篮（目标=排球）
ros2 service call /rb_mission/set_mission rb_msgs/srv/SetMission "{mission: SHOOT}"
# 传球（目标=篮球）
ros2 service call /rb_mission/set_mission rb_msgs/srv/SetMission "{mission: PASS}"
```

### 起完之后自动跑什么（**对着代码核过**）

```
IDLE
 └→ START_DELAY    规则要求的 8 秒启动延迟（期间不得有任何动作）
     └→ SEEK_BALL  视觉找目标球，边靠近边对准
         └→ ACQUIRE     吸取（没有持球传感器时按 2.5s 假定完成）
             └→ NAV_TO_ZONE  导航到动作区（投篮点/传球点）
                 └→ ALIGN        对准篮筐 / 传球架圆环
                     └→ LAUNCH       发射（持续 1.5s）
                         ├─ 还没做满 2 次动作 → 回 SEEK_BALL 继续
                         └─ 做满 2 次        → RETURN_HOME 回位 → DONE
```

**关键参数**（`src/rb_mission/config/mission.yaml`）：

| 参数 | 值 | 含义 |
|---|---|---|
| `start_delay_s` | 8.0 | 规则要求 5~15s 启动延迟 |
| `actions_per_mission` | 2 | 每环节累计 2 次动作 |
| `launch_hold_s` | 1.5 | 每次动作持续多久 |
| `acquire_seconds` | 2.5 | 无传感器时假定的吸取耗时 |

> ⚠️ **起完任务后 Ctrl-C 只是退出"监听"，任务仍在车上跑。**
> 要真停车：`set_mission IDLE`；急停：`bash tools/panic.sh`。

**盯状态：**
```bash
ros2 topic echo /mission/status
# detail 字段会说人话，例如：
#   "接近 ball_volleyball bearing=+0.12 v=0.20"
#   "GOTO (9.50,3.75) 剩余 0.32m"
#   "GOTO 完成"
```

## 四、停车 / 急停

| 情况 | 命令 | 说明 |
|---|---|---|
| **正常停** | `... set_mission "{mission: IDLE}"` | 底盘继续发零速，**电机板不会锁** |
| **急停** | `bash tools/panic.sh` | 锁 estop → 发零速 → 杀 mission/chassis |
| **硬急停** | 按车上电源开关 | **永远优先，软件不如拔电** |

> ⚠️⚠️ **永远不要 `kill -9` 底盘节点** —— 电机板看门狗会断粮锁死，
> 只能**断电 10 秒**才解得开。

## 五、故障速查（现场 30 秒定位）

```bash
bash tools/check_ready.sh      # 先跑它，一条命令看完全链
```

| 症状 | 最可能原因 | 怎么办 |
|---|---|---|
| **车不动** | 电机板锁死（今天 kill 过底盘 / 停很久） | **电机板断电 10 秒** |
| **雷达没数据** | 重复驱动抢端口 | `bash tools/boot.sh`（会自动清残留） |
| **地图全黑** | 雷达没上电 / TF 断 | `check_ready` 看哪一层；地图应在 `boot.sh` 后 30 秒出现 |
| **点目标没反应** | mission 节点死了 | `ros2 topic info /goal_pose` → Subscription 必须是 1 |
| **位姿乱飘** | FAST-LIO 发散 | `check_ready` 看 `/Odometry.x`；超 ±100m 就重启整套 |
| **车往错方向走** | `angular_z_sign` 反了 | `chassis.yaml` 改 `-1`，重启底盘 |
| **任务站着不动** | 位置判据误判 | 临时 `require_zone_compliance: false` |
| **看不到球** | 光照变了 | `perception.yaml` 的 `conf_threshold` 0.25 → 0.15 |

## 六、局间（2 分钟）

```
① set_mission → IDLE（让底盘继续发零速，板子不锁）
② 等裁判示意
③ 下一局：回 §二，从"把车摆到标记处"开始
```

**如果中途断电过：电机板已断电 → 上电后按 §二 重来一遍。**

## 七、关键数值备忘

| 项 | 值 | 备注 |
|---|---|---|
| 场地 | 14.0 × 7.5 m | 1/4 标准篮球场 |
| 控制周期 | mission 20Hz / 底盘 100Hz | — |
| `cmd_vel` 超时 | 200 ms | **别调大** |
| 定位延迟 | ~24 ms | 超 100ms 就跑 `tools/check_latency.py` 查 |
| 到点容差 | 0.05 m | `position_tolerance` |
| 接近限速 | 0.25 m/s @ 0.4m 内 | `approach_speed` |
| 导航超时 | 90 s | `nav_timeout_s`，超时自动取消 GOTO |
| 对准/吸取超时 | 25 s | `state_timeout_s` |
| 一次任务总超时 | 300 s | `mission_timeout_s`（规则每环节约 10 分钟） |

## 八、一页速查（贴车上）

```
上车：  摆标记 → 合开关 → boot.sh → check_ready 全绿
起一局：python3 tools/match_run.py            （投篮）
        python3 tools/match_run.py --mission PASS  （传球）
停车：  set_mission IDLE      （板子不锁）
急停：  panic.sh  或  按电源
车不动：电机板断电 10 秒
没地图：boot.sh 重来（30 秒）
绝不做：kill -9 底盘
```
