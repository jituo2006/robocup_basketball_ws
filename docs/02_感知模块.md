# 02 · 感知模块（rb_perception）

视觉检测：**YOLO（2 类球）+ HSV/霍夫圆（篮筐、圆环、定位柱）**。对应包 `rb_perception`。

---

## 1. 检测器一览（当前实际启用状态）

| label | type | 状态 | 说明 |
|---|---|---|---|
| `ball_basketball` | blob(HSV) | ⭕ 关闭 | 已被 YOLO 取代 |
| `ball_volleyball` | blob(HSV) | ⭕ 关闭 | 已被 YOLO 取代 |

> 而 YOLO 已覆盖这两个类别。想兜底就把 `enabled` 改回 true，但**先跑 `calibrate_color.py`**。

## 2. YOLO 球检测（当前主力）

### 2.1 模型

```
~/models/ball.onnx   9.4 MB（在仓库外，不入库）
  架构 : Ultralytics YOLO26n（2.42 M 参数）
  类别 : {0: 'basketball', 1: 'volleyball'}
  输入 : [1, 3, 640, 640]（固定尺寸，非动态）
  输出 : [1, 6, 8400] = 4 框 + 2 类
  训练 : Google Colab，ultralytics 8.4.164 导出，opset 12
```

### 2.2 配置（`perception.yaml`）

```yaml
- label: yolo
  type: onnx
  enabled: true
  model_path: "/home/user/models/ball.onnx"
  conf_threshold: 0.25     # ⚠️ 实测排球置信度只到 0.26~0.30，设 0.35 会漏检
  iou_threshold: 0.45
  input_size: 640          # ⚠️ 模型固定 640，填别的会形状不匹配报错
  every_n_frames: 2        # 隔帧推理（YOLO 是 CPU 大头），复用上次结果
  real_diameter_m: 0.24
  class_real_size: {ball_basketball: 0.24, ball_volleyball: 0.21}   # 各按真实直径测距
  only_mapped: true        # 只保留映射过的类别，其余丢弃
  name_map:
    basketball: ball_basketball
    volleyball: ball_volleyball
```

### 2.3 OnnxDetector 已实现的能力

- 自动识别输出布局：YOLOv8/v11 `(1, 4+C, N)` 与 v5/v7 `(1, N, 5+C)`，**用 nc 精确判定而非"取较小维"猜**。
- letterbox 预处理 + 反变换、纯 numpy NMS（不依赖 torch）、类别映射（自动读 ONNX 元数据里的 `names`）。
- `every_n_frames` 跳帧复用缓存：返回空会让状态机误判"球丢了"，所以**复用而不是返回空**（有测试锁住）。
- `only_mapped`：不筛的话 COCO 之类模型的 person/chair 会混进来、被套篮球尺寸算出荒谬距离。

### 2.4 换模型只需改两行

```yaml
model_path: "/home/user/models/ball.onnx"   # 换成新 .onnx
name_map: {basketball: ball_basketball, volleyball: ball_volleyball}
```

训练/导出（在 GPU 机器或 `~/yolo_env`）：

```bash
yolo detect train model=yolo26n.pt data=data.yaml epochs=120 imgsz=640
yolo export model=runs/detect/train/weights/best.pt format=onnx imgsz=640
```

> 数据建议自己拍（300~500 张/类），用现有模型**自举标注**（自动打框 + 只修错的）。
> 见 `08_已知限制` 的后续工作。

## 3. 颜色（HSV）标定 —— 只剩篮筐/圆环/定位柱还在用

```bash
# 实时采样：空格冻结 → 拖框框住目标 → 回车；可多次；c=计算写回
python3 tools/calibrate_color.py --label hoop

# 从图片 + 指定框
python3 tools/calibrate_color.py --image shot.jpg --rect 600,300,140,140 --label pillar
```

工具三个关键点：
1. **按内接椭圆采样**（不是整个矩形，四角是背景）。
2. **色相环聚类 + 丢弃背景杂簇**（< 主簇 25% 的丢掉）。
3. **用真检测器跑一遍验证**，出对照图。

**质量闸门（重要）**：掩码覆盖全图 > 15% 会**拒绝写入**并提示——这几乎总是"框太松，把地板/背景也算进去了"。实测踩过：排球被标成 `[13,0,19,32,255,255]`（饱和度下限 0），命中 71% 画面。想强行写加 `--force`。

## 4. 测试配置与生产配置是隔离的

```
perception.yaml       ← 生产：真球标定 + YOLO，给车上 rb_perception 用
perception_test.yaml  ← 冻结标准色：只给 verify_offline 的合成图视觉自检用
```

别改 `perception_test.yaml`。离线自检的合成图用标准橙色篮球，而生产配置按真球标定——
混用会让自检"误报失败"。

## 5. 启动与自检

```bash
ros2 launch rb_perception perception.launch.py
ros2 topic echo /perception/detections      # 看检出
python3 tools/view_camera.py                # 看图 + 框
```

- 帧率：JPEG 640x480 约 30fps、720p + YOLO@640 隔帧约 21fps（无 YOLO 基线 26fps）。
- 离轴误差：标定去畸变后 35° 处 0.04 mrad（未标定 60 mrad）。
