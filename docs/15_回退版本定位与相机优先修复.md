# 回退版本定位与相机优先修复

日期：2026-10-12。基于 Linux `/home/user/robocup_basketball_ws` 的回退提交
`9e4423fe4e68dfb469d5af6e724a17fa3aca846b`，只修复定位运动滞后、相机选择和观测时间戳。

## 行为变化

- 默认前摄使用 `/dev/v4l/by-id/usb-HD_Camera_Manufacturer_USB_2.0_Camera-video-index0`。
  本机当前对应 `/dev/video2`；`/dev/video0` 是后摄 LRCP。相机缺席时重试原路径，
  不自动切换到另一台摄像头。单独相机 launch 的 `device` 和整车 launch 的
  `camera_device` 默认为空，表示采用配置文件；仍可显式覆盖。
- `use_odom_pose_as_abs: true` 时，先将雷达位姿转换到车体中心和场地坐标系，
  再根据连续位姿差进行预测并更新，避免 FAST-LIO 的零 twist 导致滤波运动滞后。
  不同时积分 twist；速度输入模式仍保持原行为。安装角和安装偏移来自现有配置。
- 相机只发布新采集帧，图像、压缩图和 CameraInfo 共用读帧后的 ROS 时间戳。
  该时间是主机收到帧的时间，不能当作 UVC 硬件曝光时间；驱动缓冲延迟仍需实测。
  仅发布压缩图时跳过原始 Image 转换。
- YOLO 隔帧复用框时，单个 Detection 的 stamp 保留原推理图像时间。
  DetectionArray 的时间仍表示当前图像，其他检测器可以输出当前帧观测。
  消费端须同时检查数组和单项的时间戳，不能拿发布频率代替观测新鲜度。
- `bringup_full` 相机节点通过 `config_file` 加载自定义 YAML，避免当成 ROS 参数 YAML。

## 现场复验

重新 source 安装环境后，在实际测量的 start_pose 摆车，再启动定位链路。
先静止、直推和横推各 1m，再原地转圈；检查车体中心、方向和源时间戳延迟。
