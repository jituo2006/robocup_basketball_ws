## 5. 本次踩到并绕过的两个坑（下次跑之前必查）

### 坑 1：模型相对路径按进程 CWD 解析

```
配置写的是相对路径：../models/ball_pillar_20261015.onnx
代码按进程 CWD 解析 → /home/user/models/ball_pillar_20261015.onnx
若该文件不存在 → build_detectors 抛 NoSuchFile → 【ONNX 检测器被静默跳过】
                    → 前摄"检测器"变少 → 完全认不出球

本次绕过方式（临时）：在 CWD 落点建符号链接
  ln -sf $PWD/src/rb_perception/models/ball_pillar_20261015.onnx \
         /home/user/models/ball_pillar_20261015.onnx

⚠️ 根因未修：每换一次模型就要补一次链接，容易漏。
建议：让 detectors.py 按【配置文件所在目录】解析相对路径。
```

### 坑 2：`fastlio_mapping` 死掉会让路线无限死等

```
localization_node.py:377-381
    out = PoseWithCovarianceStamped()
    if self.last_source_stamp is not None and session_live:
        out.header.stamp = self.last_source_stamp
    # ← 条件不成立时 stamp 保持默认 0

而 test_perimeter_ball.py:322-324 的 _on_pose：
    if (... or stamp <= self.pose_stamp or stamp <= experiment_cutoff):
        return        # ← stamp = 0 → 每帧都被丢弃 → self.pose 永远为 None

test_perimeter_ball.py:567 的 wait_motion_ready：
    while self.rclpy.ok():     # ← 没有超时
        try: self.require_fresh_pose(); return
        except RuntimeError: ...   # ← 吞掉异常继续循环

⇒ 表现：卡在 "[3/5] 等待定位就绪"，日志再无输出，车一动不动。

本次绕过方式：整栈重启（清掉 lidar 会话状态），重启后 stamp 恢复正常。

⚠️ 建议：
  ① 定位节点在 source 不可用时【不要发布 stamp=0 的位姿】
     （或明确发一个"定位不可用"标志，而不是让下游靠时间戳猜）
  ② wait_motion_ready 加超时或可观测的进度输出，
     避免"看起来在跑、实际死等"这种最难排查的状态
```
