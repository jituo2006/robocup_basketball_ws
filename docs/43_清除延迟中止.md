# 清除仅由延迟触发的任务中止

2026-10-15，按用户要求删除中止分支，没有用调大计时参数代替删除。

- 上电监视：删除连续2秒 ping 不通杀掉整套程序的逻辑，触发后不再探测 ping；删除 state.json 永久锁定启动的判断。状态文件只记日志。人工急停 inhibit 保留。
- 路线：删除 ProgressWatchdog 类、全部调用和 motion-stall-seconds 参数。到点、旋转、前摄横移、后摄对正、距离取球均不再因长时间没有进展退出。
- 定位/观测：暂缺或源数据延迟时停车等待新帧，恢复后继续原目标。速度发送口在等待恢复后丢弃先前算出的指令，由下一次闭环重新计算。
- 服务：起点重置、串口机构指令、mission发射确认与停止确认没有固定总等待期限；已发出的请求始终等待同一个 future，不因延迟重发射球。
- mission：删除任务/阶段/定位等待/到位确认期限与计时重试函数。临时定位失效不进入 FAULT，不清除目标或正在等待的机构请求。
- 雷达：数据延迟/丢帧不再杀驱动或 FAST-LIO，不增加会话故障计数。临时撤销就绪，恢复后继续原会话。定位层删除心跳延迟封锁会话、里程计间隔过长清除坐标基准的逻辑，保留原坐标变换。
- 人工入口：控制台启动整套/底盘不再因等日志超过120秒/指定时长失败；控制台动作服务与 match_run 不再因服务回复或监控时长退出。

保留：用户指定上电等待5秒、机构动作的实际等待时间、急停、控制进程失联后的底盘零速、非有限数与真实位置跳变检查、真实服务拒绝与进程退出。定位和视觉的源时间有效性仍用于判断能否发送闭环速度，但不会仅因延迟结束路线。旧到位/路线 timeout 兼容参数不产生中止；旧版搜索最后一段未找到会继续搜索，不再退出；扫描分段时间用于切换搜索方向，诊断命令与关闭进程的系统等待时间不属于任务运行期限。

离线回放验证不代表实车两次传球和回位已经验收。部署时不执行运动或机构指令。
