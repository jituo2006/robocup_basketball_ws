# 03 · 标定与调参

按"先几何、后控制、最后视觉"的顺序做。**每标一项就立刻用实测数据核对。**

---

## 1. 底盘参数标定（最先，影响一切）

### 1.1 三个参数的两个常见坑

| 参数 | 代码要的 | 常见错误 |
|---|---|---|
| `width` | **左右轮中心**距离（轮距） | ❌ 填成车体外宽（更小才对） |
| `length` | **前后轮中心**距离（轴距） | ❌ 填成车体外长 |
| `wheel_radius` | 轮子**半径** | ❌ 填成直径（差 2 倍！） |

> ⚠️ 口语里"轮径 7.5cm"几乎都指**直径** → 半径要写 **0.0375**。
> 写错会让车跑得差整整 2 倍。

### 1.2 用工具两步实测（推荐，别靠猜）

运动学上这两个量是**正交**的，可以独立标定：

```
wheel_rpm = v × cos45° × 60/(2π·r)          ← 只跟【轮径】有关
转向项    = ω × hypot(w/2, l/2) × …          ← 只跟【轮距/轴距】有关
```

**前置**：车留出净空，底盘节点在跑

```bash
ros2 launch rb_chassis chassis.launch.py
```

**第 1 步 · 直行标定轮径**（车前方留 ≥2m 净空）

```bash
python3 tools/measure_chassis.py straight --speed 0.15 --seconds 6
```

它会以 0.15 m/s 走 6 秒（理论 0.90 m），然后让你用卷尺量实际距离，
自动算出正确的 `wheel_radius`。想直接写回配置就加 `--apply`。

**第 2 步 · 自转标定轮距/轴距**（车身贴张纸条当地标）

```bash
python3 tools/measure_chassis.py rotate --angular 0.5 --seconds 6
```

理论转 171.9°，量出实际转角后，它会给出应缩放的 `width/length`
（等比缩放，保持长宽比）。

**想先看理论值**（不动车）：

```bash
python3 tools/measure_chassis.py show
```

### 1.3 手工核对

```bash
python3 tools/measure_chassis.py show
```

会用当前配置算出"某速度对应多少轮速"，可与 `/chassis/wheel_speed` 对照。

## 2. 机构标定（投篮转速）

上一届的数据在 `~/Code/rc_ws/ml_ws`（148 条 `shoot_data.csv` + 5 个模型），
**但适用距离只有 1.6~4.5 m**，而 RoboCup 场地是 14×7.5 m、篮筐位置不同 → **必须重采**。

### 2.1 采数据

固定球的位置、固定角度，逐步改变发射距离与转速，记录"是否命中"。
建议覆盖：
- 距离：从三分线内到三分线外各取 5~6 个点
- 转速：每个距离上下扫 3~4 档

### 2.2 拟合

数据够 30 条以上就能拟合 `距离 → 转速`。上一届的 `ml_ws/rf.py` 可以直接复用。

### 2.3 接线到本工程

`rb_mission/config/mission.yaml`：

```yaml
launcher:
  speed: 2800      # 先用固定值
  angle: 64
```

等模型可用后，把 `rb_mission` 里 `_call_launcher` 的 `speed` 改成"按当前到篮筐距离查表"。

## 3. 相机标定

### 3.1 内参（要测距就必须做）

```bash
# 需要先装 camera_calibration
sudo apt install ros-humble-camera-calibration
ros2 run camera_calibration cameracalibrator --size 8x6 --square 0.025 \
    --ros-args -r image:=/camera/image_raw
```

标定完把 `fx fy cx cy` 填进 `perception.yaml` 的 `camera:`。

> 不标定也能跑（按假定 60° FOV 估算），但**测距会错**，
> 于是"是否到吸取距离"的判断就不准。

### 3.2 相机安装偏置

相机光轴与车体前进方向的夹角，填 `localization.yaml` 的 `camera_yaw_offset_rad`。

标法：把车摆正对着一个已知方位的目标，看 `bearing_rad` 是否等于理论值，差多少填多少。

## 4. 视觉阈值标定（**每次换球/换场地都要重做**）

2026 规则要求识别"各队自带用球的颜色/图案差异" → **阈值不是一次性的**。

流程：
1. 在实际场地的光照下拍球
2. 取色读 HSV（OpenCV 的 H 是 0~179，S/V 是 0~255）
3. 替换 `perception.yaml` 里对应 label 的 `hsv_ranges`（可以给多段，覆盖不同光照）
4. **立刻回归**：`python3 tools/make_test_image.py --check`

如果敌我两队的球颜色接近，就要靠**图案/纹理**而不是纯颜色 —— 那需要上 ONNX 模型
（`perception.yaml` 里已经留了 `type: onnx` 的接口，`OnnxDetector` 也已写好骨架，
装上 `onnxruntime` 后补 preprocess/postprocess 即可）。

## 5. 场地几何标定（**上任务前必做**）

`rb_mission/config/mission.yaml` 的 `field:` 里这些值现在都是**占位**：

| 字段 | 含义 | 怎么定 |
|---|---|---|
| `home` | 出发区中心 | 量出发区到场地原点 |
| `hoop` | 篮筐位置 | 篮架在底线中间 → x 接近 14，y = 3.75 |
| `shoot_line_radius_m` | 投篮边界线半径 | 按场地图实测 |
| `three_point_radius_m` | 三分线半径 | 按场地图实测（决定 10 分还是 30 分） |
| `pass_zone.polygon` | 传球区多边形 | 按场地图实测，填场地坐标顶点 |
| `pass_zone_target` / `shoot_zone_target` | 状态机导航到的动作点 | 手选"站在这里容易投进"的点 |

**验证**：把车推到区内的某个点，看 `/mission/state` 的 `in_pass_zone` / `in_shoot_zone_outside` 是否为 true。

```bash
ros2 topic echo /mission/state
```

## 6. 状态机调参（`mission.yaml`）

| 参数 | 作用 | 调不好会怎样 |
|---|---|---|
| `max_linear` / `max_angular` | 速度上限 | 太大：过冲、撞球；太小：超时 |
| `kp_linear` | 走位增益 | 太大：来回振荡；太小：到点慢 |
| `kp_yaw` | 转向增益 | 太大：抖动；太小：对不准 |
| `position_tolerance` | 到点判定 | 太小：永远到不了；太大：位置不稳就动作 |
| `yaw_tolerance` | 对准判定 | 同上 |
| `close_lost_distance_m` | 球曾近于此距离后消失 → 视为已吸到 | 太大：球还在远处就误判；太小：贴上去还不判 |
| `state_timeout_s` | 单阶段超时 | 太小：动作没做完就重试 |
| `start_delay_s` | 启动延迟 | **规则要求 5~15 秒，不能改出这个范围** |

**调参纪律**：一次只改一个，改完记下"改前/改后"和现象。否则会越调越乱。
