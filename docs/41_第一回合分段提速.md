# 第一回合分段提速

2026-10-15。在固定角度传球及非必要门槛清理的基础上，拆开走线和识球扫描的速度，第一回合启用分段速度配置。第二、第三回合与独立first-pass两球转运保持原速度。

## 当前第一回合速度

|动作|参数|原值|当前值|
|---|---|---|---|
|空车去中线、最终回位等纯走线|travel_mps|0.25m/s|0.50m/s|
|预装球到传球点、第二球取球后的转运|carry_mps|0.25m/s|0.35m/s|
|中线识球横移|scan_mps|0.25m/s|0.25m/s|
|取球后退回检测停车点的第一段|pickup_exit_mps|0.25m/s|0.12m/s|
|原地转向上限|turn_rad_s|0.30rad/s|0.40rad/s|
|普通到点减速区半径|approach_radius_m|0.45m|0.60m|
|到点减速区速度上限|approach_mps|0.12m/s|0.12m/s|
|后摄横移对球|--route-rear-align-speed|0.04m/s|0.04m/s|
|独立后退取球|--route-scoop-speed|0.08m/s|0.08m/s|
|后退末段最低指令|--route-scoop-min-speed|0.05m/s|0.05m/s|

载球阶段按流程标记，不是传感器入仓确认。首次启动若首球预装，就用carry_mps入场并去传球点；成功执行出球步骤后切换为空车走线；后退取球步骤完成后再切为载球转运。机构关闭的走线实验也按同样阶段选速，以便验证流程。任何发射失败都不提前切换为空车阶段。阶段状态中保存carrying，分步或重试不会丢掉此信息。

取球后先低速返回检测停车点，再沿已走路线退出，避免直接以快速转运速度退出球位。扫描接口单独读scan_mps，纯走线提速不会把识球横移也提高到0.5m/s。靠近终点仍按距离降低速度，进入原位置/角度容差即停车，没有恢复测速等待或连续帧数门槛。

## 手动调参入口

NUC文件：`/home/user/robocup_basketball_ws/tools/match_rounds.json`，`speed_profiles` → `1`。本地为同仓库的`tools/match_rounds.json`。

```json
"speed_profiles": {
  "1": {
    "travel_mps": 0.5,
    "carry_mps": 0.35,
    "scan_mps": 0.25,
    "pickup_exit_mps": 0.12,
    "turn_rad_s": 0.4,
    "approach_radius_m": 0.6,
    "approach_mps": 0.12
  }
}
```

speed_mps=0.25保留为未配置回合/字段的兼容默认值。第一回合已有速度配置时，改speed_mps不会覆盖已明确配置的分段速度。删除某个分段速度字段后，travel/carry/scan回退到speed_mps；删除pickup_exit_mps后退出段回退到正常走线速度。

转向和到点减速仍可用原CLI覆盖：`--max-ang`、`--approach-radius`、`--approach-speed`。明确传入的CLI值优先于回合配置。其它路线未配置时仍回退0.3rad/s、0.45m、0.12m/s。未提高后摄对球、后退取球速度；它们仍可用原CLI或控制台靠近速度调节。

例如 `bash tools/run_first_round.sh --max-ang 0.35` 可临时降低第一回合转速。机构开关仍由`--mechanism`/`--no-mechanism`控制，配置不会启动机器人。配置在下次启动路线时读取；分段速度也会写入控制台提示和运行日志。

## 验证与边界

离线测试覆盖完整第一回合的载球/空车速度切换、三个阶段新建Runner的状态恢复、原扫描/取球速度、异常时恢复临时速度、第二/三回合保持原速、旧配置兼容及CLI覆盖。生产goto测试验证远段输出0.5m/s，进入0.6m减速区后输出至多0.12m/s，进入原容差后停车。

当前底盘源码配置limit_vel=1.0、limit_acc=1.5、stop_accel=3.0，本次未改底盘参数；实际运行的参数和运动效果仍需现场确认。未取消定位源检查、无进展停车、急停或失联归零。0.5是纯走线速度上限，不是全程恒速，也不能由离线测试保证实际无超调、载球不掉落或整轮耗时。未执行实车运动。
