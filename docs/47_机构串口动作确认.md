# 主机机构串口：动作确认流程

修改对象：远程 `/home/user/robocup_basketball_ws`。主板固件、电流和速度参数未修改。
备份：`backups/mechanism_ack_20261016_002812/`，其中保存了修改前文件及 Git 状态。

## 行为

- `rb_launcher` 是唯一串口读取者，发布 `/rb_launcher/rx` 原始行和 `/rb_launcher/rx_event` JSON事件。事件带节点代次、递增序号、发送编号和单调时间。
- `/rb_launcher/text` 的 success 仍只表示写入；响应新增发送边界。任务按边界过滤旧回复，检测丢事件、重启、断线和其他调用者插入的命令。没有新版边界信息时拒绝自动运行。
- 接球：查询 DJI 在线、健康、已有零点及起始位置；上升90°/5RPM，确认接受并查询到两侧 HOLD、位置误差不超过1°、速度不超过1RPM；到位后保持5秒；下降0°/5RPM并确认到位，才继续底盘行驶。
- `DONE` 本身不能证明本次动作完成；ACK 后的新状态与目标位置才是到位依据。同目标已保持时，即使主板没有新的 DONE，也可通过新状态确认。
- 自动接球不执行 dji_zero。零点无效时暂停；必须由现场人员确认机构处于真实初始位置，再使用调试界面“初始化”（停止、当前位置设零及状态确认）。每次取球重新置零会导致参考位置漂移。
- 发射：停止完成、两路新鲜反馈及静止 → 人工起点确认命令并检查home → 发射被接受、新run结束且至少等待3秒（timed release 正常结果；motor current feedback high 仅记录并继续） → 再停止并确认静止 → 定时复位启动、新run正常结束 → 两路静止、零电流请求及home=1。
- DJI/VESC原运动指令及发射参数保留。VESC复位仍是固件的300机械RPM反转1200ms；主机没有增加机械底部检测。复位结果正常及home=1不证明球托真的到底，也不证明球已出手或命中。
- 主板拒绝、故障、超时、断线等均暂停当前阶段并保存原因；异常清理不额外发送 dji_stop/vesc_stop，也不重新置零、下降、发射或复位；正常动作序列及显式停止操作仍保留。底盘到点、居中、定位失效和通信失联停车保持不变。
- 运动指令不自动重发。未知结果或故障后，应现场检查实际位置和结果再决定如何继续，不能盲目重新运行整轮。

## 参数与兼容

`match_rounds.json` 的 intake_settle_s=5 是上升到位后的保持时间；命令行 `--route-intake-settle` 可覆盖。
发射后的 command_waits_s=3 是最小等待；停止/home/reset使用回复和状态确认，不依赖固定sleep。
默认接受回复超时2秒、DJI到位超时20秒、发射结束超时20秒、定时复位结果超时8秒、VESC静止/home就绪超时5秒。超过上限即失败，不放宽主板保护。
VESC状态需要ID1/2反馈年龄小于20ms、请求电流为零、发送邮箱空、速度不超过5机械RPM，连续两次状态覆盖至少150ms。

三回合及分阶段入口共用已确认流程；六按钮传球界面仍调用原脚本，无需改变按钮和映射。完整调试界面的抬起/放下/传球按钮也使用确认流程；显式单行文本工具仍是原始发送接口，不代表动作完成。
`intake_control.py` 中旧原始预设仅为历史/人工工具兼容，不用于自动比赛动作。
