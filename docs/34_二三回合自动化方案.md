## 1. 先明确一件事：动作代码是**通用**的，不需要为第 2/3 轮另写

三轮共用同一套动作实现（`Runner`）：

```
goto / scan_to / rotate_to / rear_visual_scoop / aligned_intake_approach / intake_text
        ↑ 这就是"固定路线寻球"用的那一套 ✓
```

**三轮唯一的差异只有两处**，而且都已经按规则写好了：

| 差异点 | 位置 | 回合1 | 回合2 | 回合3 传球 | 回合3 投篮 |
|---|---|---|---|---|---|
| `search_order()` | `match_round_route.py:132-139` | `['middle']` | `['middle','arc']` | `['arc','inner']` | `['inner','arc']` |
| 首球预装 | `match_round_route.py:354` | 有 ✓ | 无 | 无 | 无 |

对照规则用球表（docs/12 §3）：

```
回合2:      中线 2/0 最优 → 拿不到再扫三分弧 3/2          ⇒ ['middle','arc'] ✓
回合3 传球: 三分弧 2/篮球/2/干扰 → 再扫内线 3/篮球/1      ⇒ ['arc','inner'] ✓
回合3 投篮: 内线 3/排球/0干扰 最稳 → 再扫三分弧 4/2       ⇒ ['inner','arc'] ✓
```

**⇒ 所以第 2/3 轮不是"要写动作"，而是"要补外围 + 现场标定"。**

## 2. 三轮的分值（决定优先级）

| 项目 | 传球 PASS | 投篮 SHOOT |
|---|---:|---:|
| 进场 | 5 | 5 |
| 每次动作位置分 | 传球区内 10 / 区外 5 / 未传出 0 | 投篮线外 10 / 线内 5 / 未投出 0 |
| 命中分 | 目标区 1/2/3 → **10/30/50** | 三分线内 10 / **线外 30** / 中筐板 5 |
| 回位（承重轮在区内） | 5 | **15** |
| 时间分 | 每剩 5s 得 1 分，≤10 | 每剩 2s 得 1 分，≤10 |
| 干扰球触碰 | 每次 −2 | 每次 −2 |

```
满分: 传球 140 / 投篮 110      积分赛权重: 传球 30% / 投篮 【70%】
⇒ 三条策略结论:
   ① 【投篮必须在三分线外】10+30=40/次 vs 线内 5+10=15/次，差 25 分/次 ★
   ② 【回位是确定分】投篮 15 > 传球 5，绝不能为了多试一次而不回位 ★
   ③ 【传球命中顶部圆环 50 分是最高单项】，但先保区内 10×2 的稳定分
```

## 3. 本轮新增的专用入口（本次交付）

照 `tools/run_first_round.sh` 的样板做了三个脚本：

```bash
bash tools/run_round2.sh            # 第2轮传球：中线取2球 → 传球点 → 回位
bash tools/run_round3.sh            # 第3轮传球：三分弧/内线取2球 → 传球点 → 回位
bash tools/run_round3_shoot.sh      # 第3轮投篮：内线/三分弧取2颗排球 → Q → 回位

bash tools/run_round2.sh --mechanism   # 切到"真出球"（match 模式）
```

**设计要点**：

* **默认 `--no-mechanism`** ✓ —— 只走位姿、不发串口，先把整条路线跑通
* **`--mechanism` 切 match 模式前，先做前置检查** ✓ ——
  缺 `release.<task>.commands` 或 `aim` 时**直接退出码 2 并说清缺什么**，
  不会带着错配置硬跑（因为 `match_round_route.py:126-129` 会抛
  `ValueError('双次流程须先配置真实出球 commands 和 aim')`）
* **拒绝 `--pickup-only` / `--round-first-ball`** ✓ ——
  第 2/3 轮没有预装球，只测取球请用 `run_round_test.sh 2 pass --pickup-only`
