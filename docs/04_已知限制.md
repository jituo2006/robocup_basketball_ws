## 🔵 发现的上游库 bug（建议反馈给队里修）

这三个是自己代码里绕开了、但**根子在队内共享库里**的问题，
别的工程只要走到同样的路径也会踩：

| # | 位置 | 问题 | 触发条件 | 后果 |
|---|---|---|---|---|
| 1 | `MotorLib-For-Linux/src/dji_board.cpp` | 构造函数里 `if (can_handle == nullptr) { this->can_handle = make_shared<Can>("can0"); can_handle->can_start(); }` —— **调的是参数而不是成员**（应为 `this->can_handle->can_start()`） | 传 `nullptr` 构造 `DJIBoard` | **段错误** |
| 2 | `bupt_can_node/src/bupt_can.cpp` | `Can::~Can()` 无条件 `send_thread_->join(); recv_thread_->join();`，而这两个线程只在 `can_start()` 里创建 | 构造了 `Can` 但**没调用** `can_start()` | 析构时**段错误**（进程退出码 139） |
| 3 | `ballrobot/src/R1_server.cpp`（RoboCup 不适用） | 打不开串口时抛未捕获异常 | 串口不存在 | 节点 **abort** |

本工程的规避方式：
- #1：即使 `dry_run` 也传一个真实的 `Can` 对象，绕开 nullptr 分支
- #2：`dry_run` 下用**空删除器**持有 `Can`，让它永不析构
- #3：`rb_launcher` 改成降级 + 自动重连

**建议上游修复**（两行）：
```cpp
// bupt_can.cpp 析构
if (send_thread_ && send_thread_->joinable()) send_thread_->join();
if (recv_thread_ && recv_thread_->joinable()) recv_thread_->join();

// dji_board.cpp 构造
this->can_handle->can_start();
```

## 相对 ROBOCON 代码的取舍说明

移植时**故意没搬**的东西，以及原因：

| 没搬的东西 | 原因 |
|---|---|
| `joystick_upper_software`（手柄） | RoboCup §2.3-5 **禁止遥控** |
| `fullfield_positioning` 作为主定位 | 合规性存疑（见 P0-1） |
| `ballrobot/R1_server` 的"暂停手柄"逻辑 | 没有手柄了 |
| `R2_server` | 规则**每队限用 1 台机器人** |
| `LineTracking` | 那套是"用全场定位板跑点"，与 RoboCup 的任务流程不同 |
| `2025chassislib` 的舵轮部分 | 篮球车是全向底盘 |

**搬了但改过的**：见 `README.md` §3（修了 3 个真实 bug）。
