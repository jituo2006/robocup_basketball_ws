仍保留的限制与原因：

|模块|保留的检查|原因|
|---|---|---|
|底盘 BaseChassis / OmniChassis|急停、丢失cmd_vel时归零、速度/加速度限幅、CAN帧有效性|防止失控行驶和协议错误|
|Runner / MissionNode / 定位节点|位姿有限数、源时间戳新鲜度/顺序、定位跳变、运动指令有限数|失效反馈不能继续指导运动|
|导航 ArrivalGate / PoseFeedback|位置/朝向到位容差、独立新帧、实测速度与停稳确认|取消它们会把冲过目标或旧位置当作到位|
|运动控制|指令持续存在但目标误差连续无改善时停车|与动作总时限不同，有改善可以无限延长总行程时间；默认10秒，Runner通过motion-stall-seconds配置，Mission通过timeouts.motion_stall_s配置|
|场地/路线|实际场地边界、左右/上下端点顺序、不同搜索起终点、坐标系一致性|防止非法路径和场地外目标|
|感知/定位柱/对准|球种、框合法性、新鲜度、置信度、同步、唯一目标、安装确认、标记识别和拟合误差|它们决定输入是否可信，删掉会把错误球或错误地标用于动作|
|检测器|面积/半径/颜色/点数阈值、NMS和最大检测数量|属于识别算法与负载控制，取消不代表识别效果改善|
|相机|设备选择、曝光驱动范围/步长和读回校验、读取失败重连、线程数量|防止打开错误设备或提交硬件不支持的参数|
|串口/机构|服务等待期限、机构回应、发射确认期限、投篮标定范围/出球朝向、停止重复帧|防止指令无响应时误认为成功及重复发射|
|比赛规则|启动延迟、持球数/动作数、传球/投篮区与计分类别|是明确的比赛规则要求，不是任意任务超时|
|阶段会话|动作顺序、已完成动作去重、失败后的剩余距离计算、起点重置的服务成功|防止重复铲球、重复后退及旧场地基准续跑|
|诊断和系统操作|进程退出等待、HTTP/驱动/网络/服务调用期限|避免阻塞整个控制台，不属于正常运动动作总时限|

尚未取消的任务层限制已显式登记：视觉定位柱对准的配置总时限和最大转角、以及legacy旧视觉伺服的迭代/搜索预算。本轮没有未经验证改写这些识别/地标恢复流程。

默认取消任务总时限后：正在接近目标的动作持续进行；后摄漏检或到位确认不足时保持停车等待，用户停止/Ctrl-C仍可取消。旧route-*-timeout、route-rear-align-distance和goto-settle-timeout命令行参数保留兼容，但不再控制实际运动时限或横移距离。
