# 第一阶段两次铲球自动流程

> 当前坐标约定已更新：+Y 朝篮筐、+X 向右；柱=(5.75,0)，传球点=(3.725,4.8)，第二段终点=(3.725,0)；指定的目标点均按雷达位置解释，第一阶段要求定位柱校正后再行驶；详细约束及本次实测阻塞见《30_传球定位柱视觉雷达联调.md》。

按用户 2026-10-13 指定的训练流程封装，入口 `tools/run_first_pass.sh`。这条流程从场上取首球，不使用旧入口的首球预装逻辑，也不自动进入旧第二阶段或回位。

## 顺序

1. 车摆在出发区 A，车头沿场地 +Y；静止等待沿用 5 秒。先用已确认朝向与新鲜地标观测校正路线坐标变换。
2. 既有固定路线按新坐标换算：右转90度（朝+X），到观察点 (2.7,1.5)。实际中线为 y=0；“中线观察走廊”是旧程序名称。
3. 沿既有路径先搜索至 (2.7,4.4)，无球再搜索至 (2.7,0.6)，维持车头朝+X横移找球。前摄识别篮球即停，排球不触发铲球。
4. 转身 180°，后摄连续新帧横向对正，按雷达位姿后退，然后执行已封装的铲球时序。首球距离沿用 `match_rounds.json` 的 `middle.scoop_m=0.70`；并非雷达实时球距。
5. 铲球后重新观测地标校正，再闭环到传球点 P=(3.725,4.8)，到点停车重观测并复核。按用户确认，先保留传球串口接口，不发出球指令，继续第二段流程。
6. 保持雷达在传球点 **(3.725,4.800)**。先将车头转向 +X 并补偿雷达偏移，然后，向 **(3.725,0.000)** 横移；这段始终启用篮球检测。
7. 在途中识别到篮球立即停车，转身、后摄对正、按位姿距离后退并铲球；再次通过地标校正和到点复核，到传球点 P 停稳，脚本结束。不自动发第二球或回出发区。

新流程不用已经走过的中线折线回撤；两次铲球后直接按最新位姿去 P。并不具备在线绕障规划，沿途净空和车体扫掠仍需场地验收。

## 使用

只查看路线，不需要 ROS、不连接机器人：

```bash
bash tools/run_first_pass.sh --plan
```

只验证运动和视觉流程，不发送机构指令：

```bash
bash tools/run_first_pass.sh --no-mechanism
```

默认执行两次铲球和转运，保留传球接口、不发送出球指令：

```bash
bash tools/run_first_pass.sh
```

以后需要沿用现有放球联调指令处理第一球时，显式启用：

```bash
bash tools/run_first_pass.sh --first-pass-release drop
```

正式传球需要在 `match_rounds.json` 配置已验证的 `release.pass.commands` 和 `aim`，然后：

```bash
bash tools/run_first_pass.sh --first-pass-release match
```

`first_release` 默认 `none`：保留接口，两次到传球点均不发送出球串口。铲球仍沿用现有机构序列，可通过 `--no-mechanism` 关闭全部机构。当前流程未确认第一球已离开机构，两次铲球动作完成不等于成功收存两球。待调好后可选择 `drop` 或配置已验证的正式 `match` 指令。`drop` 发 `dji_move 1 0 5`，仅表示放球联调指令下发，不能证明实际出球。只检查前置条件可加 `--dry`；此时仍需定位等节点，不接管 mission、不执行路线。

运行入口沿用现有接管机制；没有自行启动雷达、底盘或相机。脚本默认机构开启，`--no-mechanism` 可关闭；使用现有 ROS 域或缺省域 2。Ctrl-C、定位过期/跳变或内部动作失败均停车退出。每次重新运行须摆回出发区，不能在传球点重开并把那里当成 A 起点。

## 配置与验收

`tools/first_pass_route.json` 保存返回点、第二段终点、第二段观察朝向、第二次后退距离和首球处理模式。传球点、首段搜索端点、速度、起点继续从 `tools/match_rounds.json` 读取。默认第二段朝向 0°、第二次后退 0.70 m 沿用首段初值，需按该段实际球距与视野调试；不是经过第二段实测的标定结果。

用户指定的 y=0.000 保留原值，不偷偷向场内夹紧。这是底盘参考点落在场地边线上；运行到终点时车体是否越界，需要按整机包络检查。第二段无篮球时到此点停车并返回失败，不盲铲、不伪报两球完成；首段无篮球则不进入第二段。第一球出球指令失败时不继续找第二球。定位坐标变换整条流程保持同一个起点，取球和到 P 后都不重设原点。

测试直接执行流程与已有生产到点逻辑，检查动作顺序、精确坐标、不同起始朝向、第二球提前触发、无球、机构失败、取消及参数恢复。仅模拟反馈，不证明实际入仓、出球、现场检测准确率或停车精度。本次同步源码与脚本，没有启动实车运行。

## 前端入口

控制台新增“第一阶段传球：两次铲球转运”，点击“启动两次铲球流程”即可运行上述独立流程。可分别调整两次靠近距离（0.03–2 米）、靠近速度（大于 0 且不超过 0.25 米/秒），并开关铲球机构；停止按钮使用现有调试脚本停止接口，运行状态及实时日志共享现有显示。

前端固定传入 `--first-pass-release none`，不发送传球出球串口；第二次到传球点停车。第 1 次距离映射 `--round-middle-scoop`，第 2 次映射 `--first-pass-second-scoop`。只读接口 `/api/first-pass-config` 读取现有路线配置，读取页面不会启动机器人。

验证：Linux 前端参数/API、两次铲球流程及原回合流程共 60 项测试通过；浏览器确认新入口和参数显示。未进行实车运动验证。
