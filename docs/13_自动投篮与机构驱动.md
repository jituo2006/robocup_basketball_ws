# 按距离自动投篮与机构驱动

本次基于 GitHub `main` 的 `8de9233`，保留此前规则审核改动。自动规划仅用于 SHOOT（本届规则目标球为排球），PASS 仍使用原来的独立固定参数。尚未进行实机出球或命中率验证。

## 自动计算链路

1. 使用新鲜的 `/localization/pose` 与 `field.hoop` 计算篮筐在底盘坐标系中的位置，再减去出球点偏移得到水平射程。
2. 对准时按出球方向控制底盘朝向，避免有安装偏角的相机对准了但发射口没有对准。
3. 发射前要求篮筐检测消息和检测本身的源时间戳均新鲜、置信度达标，并校验相机方位与地图一致。
4. 相机 `distance_m` 来自 `fx × 实际直径 / 像素宽度`，按光轴深度处理；结合右正方位角、相机安装位置/朝向换算为水平位置。相机距离有效时先检查与地图目标的位置差，再按 `vision_weight` 融合两个水平射程。没有有效测距时默认使用地图距离，但仍要求视觉方位校验；`require_camera_range: true` 可强制要求测距。
5. 用融合射程在实测表的相邻两行之间线性插值，计算并取整 `speed` 和 `angle`。只在表内插值，拒绝外推、乱序表、非有限数值和协议范围外的指令。
6. 参数在调用服务时计算一次，该次重复帧保持同一组参数，避免发射途中视觉抖动改变指令。

定位、相机或标定失败时进入 FAULT，保留具体原因，不发送发射请求。地图与相机明显不一致时不会静默采用旧转速。决赛篮筐移动后需更新真实篮筐坐标；本次未加入动态篮筐位置跟踪。

## 标定接口

配置：`src/rb_mission/config/mission.yaml` 的 `launcher.automatic`。修改 YAML 后重启任务节点生效。

- `enabled`：仅控制 SHOOT 是否使用自动参数；关闭后用 `launcher.speed/angle` 固定值进行人工标定。
- `map_confirmed`：测量并填写当前 `field.hoop` 后设为 true。
- `camera_x_m / camera_y_m / camera_yaw_rad`：相机光心相对底盘定位原点的水平安装偏移与朝向。
- `launch_x_m / launch_y_m`：出球点相对底盘定位原点的水平偏移。发射水平轴假设朝向底盘 +x。
- `detection_timeout_s / min_confidence / bearing_tolerance_rad / range_tolerance_m`：观测准入与一致性门限。
- `vision_weight`：通过一致性检查后，视觉射程的融合权重，范围 0..1。
- `table`：至少两行 `{distance_m, speed, angle}`，按距离严格递增。距离是出球点到篮筐的水平距离；角度保持下位机协议单位，不能直接假设为物理仰角度数。

默认 `enabled: true`、`map_confirmed: false`、`table: []`，因此目前自动发射会被拒绝。没有将旧固定值伪装成射程表。现场需要用实际排球、固定篮筐高度、真实相机内参及篮圈尺寸采集多距离数据；高度、球型或机构改变后重新标定。建议覆盖拟使用射程并记录多次试投结果。

## 驱动修复

- 原节点仅更新动作/转速/角度变量，未调用 `put_packet()`，导致发送初始化全零缓冲区。现在首次服务发送和后续定时发送前均封装 11 字节旧协议帧：`+ | 动作 | speed uint16 | angle uint16 | CRC32 | *`。
- 串口不可用时拒绝动作，不在重连后自动补执行。写失败时清除活动状态并标记端口不可用。
- 夹爪、滑轨开关指令仅发送一帧，避免 50Hz 重复切换；投篮等旧协议连续命令保留定时重复发送。
- STOP 仍是“停止重复发送”，不能代替下位机物理急停，也不能证明已出球。

## 验证边界

测试使用合成射程表作为夹具，数值不是实机标定。覆盖插值、端点、越界、坐标旋转与偏移、方位正负号、光轴深度换算、相机地图不一致、过期检测以及真实 ROS 服务请求参数。

串口测试启动真实 `rb_launcher_node`，只连接 PTY 虚拟串口，检查动作码、转速、角度、CRC、STOP、开关单帧和拒绝请求后的重连行为。没有向真实机构设备发送命令。
