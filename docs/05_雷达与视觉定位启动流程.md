# 05 · 雷达 + 视觉定位 启动流程

> 方案：**车载雷达（Livox MID360 + FAST-LIO）+ 规则提供的定位柱（视觉）**
> 不用外部全场定位板 —— 规则 §2.4 的场地器材清单里没有它，有合规风险。

---

## 为什么是这两路

| 来源 | 作用 | 特点 |
|---|---|---|
| **雷达 FAST-LIO** | 提供连续的绝对位姿（10 Hz） | 短期准、长期会漂 |
| **视觉定位柱** | 提供方位角校正（规则专门放的视觉基准） | 不漂，但只在视野内有效 |
| 里程计 twist | 预测 | 高频、有累积误差 |

融合后：雷达保证连续可用，定位柱把漂移拉回来。

> 规则 §2.4-5：定位柱 **直径 20cm、高 1m、蓝绿相间**，放在"传球目标位/投篮目标位"。
> 它本来就是给你做视觉定位/对准用的。

## 一、前置：雷达网络（**最容易卡在这里**）

### 1.1 先核对 IP 三处是否一致

本机存在一处**已知不一致**：

| 位置 | 值 |
|---|---|
| `~/lidar_360/ws_livox/src/livox_ros_driver2/config/MID360_config.json` | 主机 **192.168.1.110** |
| `~/lidar_360/start.sh` | 主机 **192.168.1.50** |
| 雷达自身 | **192.168.1.193** |

**Livox 驱动用 `host_net_info` 里的地址收发数据 —— 网卡 IP 与配置不一致时，点云永远不会到达。**

```bash
# 一条命令把所有副本、生效情况、网卡匹配都查清楚（推荐）
python3 tools/check_lidar_net.py --ping
```

> ⚠️ 手动查的话注意 JSON 结构：`host_net_info` **嵌在 `MID360` 里面**，
> 不在顶层（写成 `d['host_net_info']` 会 KeyError）：
> ```python
> d = json.load(open('.../MID360_config.json'))
> print(d['lidar_configs'][0]['ip'])              # 雷达 IP
> print(d['MID360']['host_net_info']['cmd_data_ip'])   # 主机 IP ← 注意这一层
> ```

### 1.2 ⚠️ 改配置必须改 install 那份（否则不生效）

实测确认：配置是**拷贝**不是软链接，而 launch 用
`os.path.realpath(__file__)` 定位到 **install** 目录：

```
ws_livox/src/.../config/MID360_config.json                   ← 源头
ws_livox/install/livox_ros_driver2/share/.../MID360_config.json   ← ★ 驱动实际读这份
```

**只改 `src/` 里的不重建，配置不会生效。** 两种做法：

```bash
# 做法 A（推荐）：改网卡去匹配现有配置，不用重建
sudo ip addr add 192.168.1.110/24 dev enp114s0

# 做法 B：改 src 后重建（或直接改 install 那份）
cd ~/lidar_360/ws_livox && colcon build --symlink-install --packages-select livox_ros_driver2
```

### 1.3 注意别 source 错工作空间

本机有两套 livox 驱动，**用的是不同雷达**：

| 工作空间 | 雷达 IP | 主机 IP |
|---|---|---|
| `ws_livox` | 192.168.1.193 | 192.168.1.110 |
| `ws_livox_38` | 192.168.1.138 | 192.168.1.50 |

本工程只 source `ws_livox`。

**统一成一个值**（推荐让网卡跟着配置走）：

```bash
# 假设配置里主机是 192.168.1.110，就把网卡设成 .110
sudo ip link set enp114s0 up
sudo ip addr add 192.168.1.110/24 dev enp114s0
ping -c 3 192.168.1.193          # 必须通，不通后面全都白搭
```

> ⚠️ 改完请同步更新 `start.sh` 与文档，避免下次又踩。

### 1.2 确认雷达工作空间已构建

```bash
ls -d ~/lidar_360/ws_livox/install ~/lidar_360/fast_prop_ws/install
```

## 二、标定（**上车前必须做，只要 3 分钟**）

### 2.1 定"摆车位"

`src/rb_localization/config/localization.yaml`：

```yaml
odom_frame_conversion:
  enabled: true
  zero_on_first: true
  start_pose:            # ← 开机时车被摆在场地里的哪个位置
    x: 1.0
    y: 1.0
    yaw: 0.0
  sensor_to_base_x: 0.0  # 若 start_pose 指的是车体中心而雷达不在中心，填偏移
  sensor_to_base_y: 0.0
  sensor_to_base_yaw_deg: 0.0
```

**操作规范**：
1. 把车推到出发区的**固定标记点**（建议贴个十字胶带在地面）
2. 用车头对准场地 **+x 方向**（或你定义的某个基准方向）
3. 量出这个点在场地坐标里的 `x, y`，填进 `start_pose`
4. **以后每次开机都用同一个点、同一个朝向** —— 这是这套方案成立的前提

> 旋转量由 `start_pose.yaw − 首帧yaw` 自动算出，
> **不需要**手填 `-90°` 之类的轴偏（那正是 ROBOCON 老代码容易填错的地方）。

### 2.2 填定位柱坐标

```yaml
landmarks:
  - {x: 10.5, y: 3.75}    # 传球目标位的定位柱
  - {x: 9.5,  y: 3.75}    # 投篮目标位的定位柱
```

**不填的话视觉校正不会生效**（节点会明确告警）。
每轮抽签后位置可能变，比赛当天按实际摆放填。

## 三、启动

### 一条命令（推荐）

```bash
cd /home/user/robocup_basketball_ws
source /opt/ros/humble/setup.bash && source install/setup.bash
ros2 launch rb_bringup bringup_lidar_vision.launch.py
```

它会按时间顺序拉起：

```
t=0s    Livox MID360 驱动        (ws_livox)
t=4s    FAST-LIO                 (fast_prop_ws)  → /Odometry
t=12s   视觉 / 底盘 / 机构 / 定位 / 任务
t=14s   可选 RViz（rviz:=true）
```

常用参数：

```bash
... bringup_lidar_vision.launch.py rviz:=true                 # 开 RViz 看建图
... bringup_lidar_vision.launch.py dry_run:=true              # 不发 CAN
... bringup_lidar_vision.launch.py image_topic:=/camera/image_raw
... bringup_lidar_vision.launch.py ros_domain_id:=2
```

### 或者手动分三段（调试时更清楚）

```bash
# 终端 1 · 雷达驱动
source /opt/ros/humble/setup.bash
source ~/lidar_360/ws_livox/install/setup.bash
export ROS_DOMAIN_ID=2
ros2 launch livox_ros_driver2 msg_MID360_launch.py

# 终端 2 · FAST-LIO
source /opt/ros/humble/setup.bash
source ~/lidar_360/ws_livox/install/setup.bash
source ~/lidar_360/fast_prop_ws/install/setup.bash
export ROS_DOMAIN_ID=2
ros2 launch fast_lio mapping.launch.py \
  config_path:=$HOME/lidar_360/fast_prop_ws/src/FAST_LIO_WITH_PROPAGATE/config \
  config_file:=mid360.yaml rviz:=false

# 终端 3 · 本工程
cd /home/user/robocup_basketball_ws
source /opt/ros/humble/setup.bash && source install/setup.bash
export ROS_DOMAIN_ID=2
ros2 run rb_localization localization_node --ros-args \
  -p config_file:=$PWD/src/rb_localization/config/localization.yaml
# 再依次起 perception / chassis / launcher / mission
```

## 四、逐步验证（每步不通就别往下走）

### ① 雷达原始数据

```bash
ros2 topic hz /livox/lidar      # 期望 ~10 Hz
ros2 topic hz /livox/imu        # 期望 ~200 Hz
```

**不通** → 回到 §1 查网络。

### ② FAST-LIO 里程计

```bash
ros2 topic hz /Odometry         # 期望 ~10 Hz
ros2 topic echo /Odometry --once
```

**不通** → 看 FAST-LIO 终端；常见原因是点云没进来（回到 ①）。

### ③ 场地坐标变换（**最关键**）

启动 localization 时日志里会打印一行：

```
odom→field 变换已确定: 首帧=(x, y, θ), 旋转=φ, 摆车位=(X, Y, Ψ)
```

```bash
ros2 topic echo /localization/pose --once
```

**验收**：
- 刚启动、车没动时，`x/y` 应该**正好等于** `start_pose`
- 抬头/推车，`x/y/yaw` 跟着变，方向正确
- 把车往场地 +x 推 1 米，`x` 应增加约 1 米

> 不对就检查：`start_pose` 填对了吗？车摆正了吗？

### ④ 视觉定位柱校正

```bash
ros2 topic echo /perception/detections --once     # 有没有 pillar
ros2 topic echo /localization/ok                  # 应为 true
```

让定位柱进入相机视野，看 `/localization/pose` 是否**小幅收敛**（而不是跳变）。
若跳变 → `bearing_std` 调大，或检查 `camera_yaw_offset_rad`。

## 六、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `/livox/lidar` 没有数据 | 网卡 IP 与 `MID360_config.json` 不一致 | 回 §1 |
| `/Odometry` 没有 | FAST-LIO 收不到点云；或工作空间没 source | 检查 `/livox/lidar` 与终端 source |
| FAST-LIO 位姿跑飞（几百米） | 回放时循环、时间戳回跳；或场地太空旷特征少 | 见 `docs/04` 已知限制 |
| `/localization/pose` 一直是 0 | `odom_frame_conversion.enabled` 没开，或 `/Odometry` 没进来 | 看节点启动日志 |
| 定位缓慢漂移 | 定位柱校正没生效 | 填 `landmarks` |
| 定位在定位柱出现时跳变 | `bearing_std` 太小 / 相机朝向偏置没标 | 调参 + 标 `camera_yaw_offset_rad` |

## 七、这套方案的已知局限（`docs/04` 有完整列表）

1. **长时间纯雷达会漂** → 必须靠定位柱拉回；没有定位柱在视野时会退化
2. **场地空旷时 SLAM 特征少** → 篮球场比 ROBOCON 场地平坦，建议实测漂移量
3. **`start_pose` 必须每次一致** → 建议地面贴定位标记，做成开机检查项
4. **定位柱位置每轮可能变** → 需要现场填 `landmarks`（长期可做成自动识别+匹配）
