## 本次修正

原 Runner 进入距离容差即返回成功，没有确认停止；现在复用任务节点的 `ArrivalGate` 和 `PoseFeedback`：位置在容差内、实测线速度不超过 0.03 m/s、实测角速度不超过 0.05 rad/s，连续新源帧稳定 0.5 秒后才完成。重复发布旧位置不会推进确认。漂出目标后以不超过 0.08 m/s 回调，首次进入容差后 5 秒仍无法稳定则失败。

到位分支同样要求定位及雷达里程计源时间戳有效。动作总超时使用单调时钟；任何异常、取消、失败与成功均执行停车。四元数先归一化，避免非单位四元数造成方向误判。

任务节点恢复 `limits.face_travel` 的实际作用，全向平移默认不追着目标转头；正确应用接近限速。故障/急停阶段及定位过期时拒绝新 GOTO；RViz 目标或定位输入的坐标系不匹配时拒绝，避免把 `camera_init` 坐标误当作 `field`。

## 可调参数

三回合和固定路线 CLI：

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `--step-tol` | 0.02 m | 回合调用的到点位置容差，沿用原值 |
| `--goto-stop-speed` | 0.03 m/s | 停稳平移速度上限 |
| `--goto-stop-yaw-rate` | 0.05 rad/s | 停稳角速度上限 |
| `--goto-settle-seconds` | 0.5 s | 连续新定位帧稳定时间 |
| `--goto-settle-timeout` | 5 s | 首次进入容差后的确认期限 |
| `--goto-velocity-window` | 0.15 s | 源时间戳位姿差分测速窗口 |
| `--goto-correction-speed` | 0.08 m/s | 到点后纠偏速度上限 |

测速窗口必须小于 `--pose-timeout`，稳定时间必须小于确认期限。普通通行上限沿用 0.25 m/s，接近速度服从 `--approach-speed`，不再因关闭视觉伺服而忽略此参数。

任务节点新增可在线修改的 `limits.approach_radius_m`、`limits.approach_speed`，默认读取现有 YAML。`limits.face_travel` 从 YAML 读取，修改后需重新加载节点。`topics.field_frame` 可指定 RViz 接受的坐标系，缺省 `field`；它必须与实际定位输出一致。
