# 六按键投篮控制 UI

NUC目录：`/home/user/robocup_basketball_ws`。桌面“投篮控制”手动打开8090界面，选择A/B区和第1/2/3轮；不开机自启。设备状态检查、后台整车准备和路线任务交接沿用当前控制台。

## 六个脚本

- `tools/run_shoot_A1.sh` / `run_shoot_B1.sh`：首球预装→Q投篮→中线取第二球→Q投篮→回位。
- `tools/run_shoot_A2.sh` / `run_shoot_B2.sh`：中线取第一球→Q投篮→三分弧取第二球→Q投篮→回位。
- `tools/run_shoot_A3.sh` / `run_shoot_B3.sh`：两颗均先搜索三分弧，无球才搜索内线，每颗取球后到Q投篮，最后回位。

默认开启机构并使用正式投篮`match`流程。以B1为例：

```bash
cd /home/user/robocup_basketball_ws
bash tools/run_shoot_B1.sh
```

`--no-mechanism`可关闭机构，底盘仍会行驶。六入口固定场地、轮次、首球模式和完整流程，复用`run_shoot_round.sh → run_round_test.sh → test_perimeter_ball.py`。

## 后端接口

- `POST /api/shoot/run`：JSON `{"side":"B","round":1}`；设备未就绪返回409，接受返回202及id、task=shoot。
- `GET /api/shoot/state?id=<id>&after=<cursor>`：任务状态、日志、退出码、硬件状态、后台准备状态。
- `GET /api/hardware/state`、`GET /api/boot/state`保持原行为。
- 投篮模式下旧`POST /api/pass/run`返回409并提示刷新，旧传球页面不会启动投篮。

映射文件`tools/shoot_actions.json`每次点击重新读取；原`pass_actions.json`和传球模式仍保留。启动器传入`--task shoot`选择投篮模式。桌面快捷方式文件名、systemd单元名继续使用robocup-pass-console，避免重复入口及服务。

## 手动调整

点位、速度、取球距离与串口时序仍在`tools/match_rounds.json`，本次未改这些参数。按A区写坐标，B区由`mirror_to_b()`镜像并应用现场已有`b_y_adjustments_m`。不要把B区Y负坐标直接写入A区参数。

- `release.shoot.point/aim`：投篮点/瞄准目标。
- `search_order.shoot`：三轮、两阶段搜索区域顺序。
- `arc.radius_shoot/angles_shoot`、`inner.x_shoot`：投篮扫描路径。
- `match_round_route.py::search_plan`：扫描点与前摄朝向。
- `RoundRoute.crossing_via/carry_via/action_point/home`：中转、转运、投篮点与回位。
- `match_round_steps.py::execute_step`：实际整轮动作衔接。

本次同时修正投篮前摄朝向：内线朝-X，内侧弧线径向朝外；传球朝向保持原值。路线几何未调整，实际净空、排球取球效果及命中率仍需现场验证。

## 页面底部：底盘往返（2026-10-16）

已将独立“保底”合并到投篮控制页面最下面，独立快捷方式、8091 服务和模式切换程序已移除。桌面仅使用“投篮控制”打开 8090 页面。

- 往返只检查底盘：DJI 板、四路电调反馈、速度模式、使能、CAN 连接及共享驱动正常；不要求雷达或定位。
- 点击“执行往返”：零速准备 0.6 秒 → 向车体右侧约 2 米 → 停车 1 秒 → 向车体左侧约 2 米 → 零速收尾 1 秒。速度上限 0.25 米/秒、加速度 0.3 米/秒²，返回后结束，可重新执行。
- “停止”仅停止底盘往返，不会误停止投篮回合。运行任何一种任务时，另一种及重复启动都返回409；多个页面也共用该互斥。投篮回合不再通过点击另一个回合中途替换。
- 沿用 `tools/fallback_config.json` 的左右距离标定参数。现有轮速话题是命令值，距离按速度/时间积分估算，不能保证实测恰好两米；没有雷达闭环修正。
- 保留无指令 TTL 策略；诊断状态过期只阻止新任务。明确未就绪、驱动退出/重启、其他速度发布者、手动停止和任务完成会结束本次往返，恢复后不会自动续跑。

新增接口：`POST /api/shoot/chassis-trip/run`（JSON `{}`）、`GET /api/shoot/chassis-trip/state`、`POST /api/shoot/chassis-trip/stop`。原 `/api/shoot/state` 增加 `chassis_trip`，包含全局任务占用、底盘状态、往返阶段和参数。旧 `/api/console/prepare-fallback` 返回410，不再切换程序。

底盘驱动统一由 `robocup-console-chassis.service` 管理，手动打开界面时启动，无需等待雷达；不开机自启。整车启动使用 `start_chassis:=false`，雷达重连不清理底盘节点或重配 CAN。手动运行完整 `boot.sh` 时，如果共享驱动已运行，需要传入该参数。

部署/迁移脚本：`python3 tools/install_console_trip.py`。脚本检查任务空闲并冻结新任务后迁移，备份旧服务和入口；不会执行实车往返。
